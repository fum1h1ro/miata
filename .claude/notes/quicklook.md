## プレビュー（Quick Look）

- **テストの罠**：ヘッドレスのハーネスでも、覆いを載せる親はウィンドウに入れておくこと（ウィンドウ外での `close` は abort する）。`QLPreviewView` の `setPreviewItem:`/`close` をメソッド差し替えで記録すると、`close` 後の設定などの違反を検出できる。
- **テスト（倍率とピンチ。リポジトリ外のスクラッチ。軽め）**：`ql_zoom_test`（実物の `QuickLookView` を、画面の隅に出した小さなパネル（キーにならない・アクティブにしない）に載せる。アプリのオブジェクトにリンクして、署名した小さな `.app` の中から動かす。**1 回の起動で 1 シナリオ**：QuickLookUI は、種類を続けて切り替えると、内部の KVO の例外（`QLScrollController _teardownScrollers`、`displayedDisplayBundle.*`）で、間欠的に落ちた。Miata では未確認）。シナリオは、`web`（xlsx。指定・読み戻し・×1.25 の繰り返し・丸め・窓経由のピンチ（広げる・縮める。前後で first responder が動かないことも、見張りのビューを first responder にして見る）・スクロール（`evaluateJavaScript` で `window.scrollY` を読む。先へ送って動き、逆向きで戻る。**200% に拡大した状態でも、縦横に動く**: WebKit の `magnification` は視覚ビューポートの拡大で、`scrollY` ではなく `visualViewport.pageLeft/pageTop` に出る）・xlsx → xlsx / docx で 100% に戻る）、`text`（txt。同じ + スクロール（`NSScrollView` の表示位置。200% の縦横も、別のファイルを読み直して、きれいな状態で）+ txt → md）、`remote`（png。ズームできない・ピンチで落ちない）、`guard`（偽の中のビューがピンチ・スクロールを戻してくる状況で、再入しない）、`hide`（Hide で nullopt・隠れている間のピンチ・スクロールで落ちない・作り直しで 100%）、`pdfscroll`（PDF のスクロールを、画素で見る。動かなかったので、動くことは要求せず記録だけ。陽性対照と、何もしない対照つき）。`lua_test`（画面なし。実物の `lua_command_quick_look_zoom` を本物の `lua_State` に登録して、表示していないときの nil と、不正な引数のエラーを見る）。変異 5 件（ピンチの再入ガード・`AllowMagnification`・スクロールの再入ガード・スクロールの転送（テキスト・WebKit）を外す）は、期待したシナリオだけが落ちた。**罠**：(1) 合成したピンチは、`CGEventCreate` + type 29 + フィールド 110=8(magnify) / 113=倍率(double) / 132=位相(1 開始・2 途中・4 終了) → `[NSEvent eventWithCGEvent:]` で `NSEventTypeMagnify` になる（往復で確認。type 30 の CGEvent は「unrecognized」）が、そのままでは `windowNumber` = 0・画面座標なので、isa を、`windowNumber` / `window` / `locationInWindow` を返すサブクラスに差し替えて（インスタンスのサイズが同じことを確かめる）、`[window sendEvent:]` で振り分けさせる。(2) 画像・PDF の画素の確認は、署名した `.app` から、`screencapture -x -R x,y,w,h`（領域）で撮る（ウィンドウ単体のキャプチャ `CGWindowListCreateImage` は、別プロセスの描画が真っ白だった）。陽性対照（プレビューの大きさを変えると画素が変わる）と、何もしない対照（差分 0）を、必ず入れる。(3) QuickLookUI の `close` は、ウィンドウに載っている間に 1 回だけ（前述）。シナリオの最後に `Hide()` してから終える。(4) 合成ピンチは、何発効くかが実行ごとに変わる（同じ 8 発で、倍率が 1.331 になった回も 2.144 になった回もあった）ので、倍率の絶対値ではなく、向き（1.0 より大きい・前より小さい）と範囲で確かめる。(5) **合成スクロールは、位相つき（トラックパッドの実物の並び。開始・途中・終了）を、`NSScrollView` が受け付けない**：開始の分だけ効いて、以降を無視する（開始に値を持たせても、スクロール回数のフィールドを足しても同じ。覆いへ直接・`NSScrollView` へ直接でも同じなので、覆いの転送のせいではなく、ジェスチャの状態が進まない合成の限界）。位相なしのピクセル単位（`CGEventCreateScrollWheelEvent2(…, kCGScrollEventUnitPixel, …)`）か、行単位（マウスのホイール）なら、窓経由で 10 発が 300px 動いて、逆向きで戻る。試験は、位相なしのピクセル単位を使う（転送の経路は、位相の有無によらず同じ）。ウィンドウ座標を返すサブクラスへの isa の差し替えは、ピンチと同じ。(6) WebKit 側のスクロール位置は、`evaluateJavaScript:@"window.scrollY"` で読めた（QuickLook の `QLWeb2View` でも）。(8) 25%〜400% の極端な拡大縮小を繰り返した後は、テキスト層の状態が変わる（表示幅が、倍率から計算した値と合わなくなり、横スクロールの確認が通らなくなった）ので、拡大した状態のスクロールの確認は、別のファイルを読み直してから行う。(7) PDF の画素の確認は、撮影した領域に、無関係な別のウィンドウ（通知など）が重なることがある。何もしない対照の差分を見て、ノイズの大きさを知っておく。
- **未確認（実機）**：本物のトラックパッドでのピンチ・スクロール（合成イベントでの確認のみ。スクロールは、位相なしだけ。位相つき・慣性は、実機）、画像・PDF・json のスクロール（合成では動かなかった）、キーウィンドウでの first responder（試験のパネルはキーにならない）、`quick_look_zoom` の `"in"` / `"out"` / `"reset"` を、表示中のプレビューで通すこと（`lua_test` は「表示していない=nil」の経路だけ。算術は、`SetZoom` の読み戻しの試験で見ている）、画像・PDF・json が、本物のイベントなら受けるか、macOS 27.0 以外での種類ごとの作り
