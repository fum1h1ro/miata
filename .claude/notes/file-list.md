## ファイル名の頭のアイコン

- **未確認（実機）**：(1) ダウンロード前（`<CLOUD>`）のファイルに `iconForFile:` を呼ぶと、ダウンロードが起きるか。今は、そのとき呼ばない安全策（種類のアイコンにする）。外す前に、iCloud の未ダウンロードのファイルで、`st_blocks` の前後を比べる（`<CLOUD>` と同じ方法）。(2) ネットワークボリューム（SMB・NFS）で、パスごとの `iconForFile:` が遅いか（行ごとに I/O が要るかもしれない。同期で、メインスレッド）。(3) クラウドストレージの中の `.app`。(4) Retina と非 Retina のディスプレイを行き来したときの見た目。(5) ユーザーの実機（Osaka 20pt・実際の `init.lua`）での見た目と、`.` キー。(6) Finder が付けるタグ・同期状態のバッジが、`iconForFile:` に載るか（載らないはず）

## 空のディレクトリ（ファイルもフォルダも1つも無い）

- **テスト**：実物の `Application::Initialize()` を模擬の `.app` から起動し、**1回の起動で1つのシナリオだけ**を実行する（落ちるシナリオを特定するため）。空のディレクトリに対する各コマンド・キー、ファイルがあったフォルダが空になった後（外部の変更 → 再読み込み。古い一覧の領域が残る形）、空のフォルダにファイルが現れた後、空でない一覧の通常の操作（マーク・リネーム・コピー・Enter）。**関係するソース（`View.mm`/`BrowserView.mm`/`FileListView.mm`/`Application.cc`/`FileListModel.cc` ほか）を `-fsanitize=address` でビルドし直した `.o` と差し替えてリンクして、実行する**（普通のビルドは、修正前でも通ってしまう）。ガードを1か所ずつ外した変異で、すべて落ちる（検出できる）ことを確かめた

## 名前が UTF-8 として不正なファイル

- **テスト**：実ファイルは作れないので、**模擬のエントリ**（存在しないパスの `directory_entry` から `FileEntryModel` を作り、`FileListModel` の `entries_` に入れて、`path_.Value(...)` で通知する）で、並べ替え（すべての基準）・描画・検索・マーク・リネームの対象を確かめる。そのほか、Enter で入れないこと（`Path() / Name()` を `JumpToOrReport` に渡す。`IsDirectory` は模擬のエントリでは真にできないので、その呼び出しを直接行う）、リネームの流れ（`Miata.command.dialog_input` を Lua で差し替えて、`rename` をコルーチンなしで走らせる。初期値のまま確定すると改名を試みず、足して確定すると試みて、実在しないので失敗のダイアログが出る）、Lua の `jump_to` に不正なバイトのパスを渡すこと（文面を直す前は SIGABRT）も確かめた。ゴミ箱は、**必ず失敗するケース（存在しないパス）だけ**に向ける（成功すると、実際にゴミ箱へ移る）。名前に加えて、**拡張子の中だけが不正な名前**（`file.t\xffxt`）も入れる（拡張子の並べ替えは、名前とは別の文字列を NSString にする）。`Utf8` の単体テストは、NSString を答えにして、1〜2バイトの全パターン・境界値・ランダム150万件を突き合わせる（上記の `A9` の癖は、食い違いに数えない）。**`std::string` は NUL で終わるので、範囲外を1つ読んでも落ちない**：ちょうどの大きさのヒープ（NUL で終わらない）に写して、AddressSanitizer で確かめる。変異テストでは、「修復後は起きない」ガード（`UTF8String` が NULL のとき）は、到達できないので生き残る（落ちないための保険）
