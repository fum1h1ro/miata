# ファイル操作（コピー・移動）と進捗パネル — テスト・実測・未確認の記録

> 自動では読み込まれない。テストを書く・直す・検証するとき、実機で確かめることを探すときに読む。
> 設計の決定と罠は `.claude/rules/file-operations.md`。

## ファイル操作（コピー・移動）

### 始める前に断る（`FileOperationGuard`）

- **テスト**（リポジトリ外のスクラッチ）：`file_guard_test`（AppKit なし。ASan + UBSan。実ファイル・実スレッド。122 件。3 つの断る場合、断らない紛らわしい場合（`foo`/`foobar`・兄弟・普通の衝突・親の兄弟）、リンク・`..`・大文字小文字・ハードリンク、調べられない場合、5000 件（28 ms ほど）、**ディスクイメージ（`hdiutil create` + `attach -nobrowse`。権限は要らず、Finder にも出ない）で別のボリューム**、`Run` の防御（ガードを通らずに直接 `Start`）、普通の操作が変わらないこと）と、`ops_test` の `guard_*`（実物のアプリで、断りのダイアログ・ジョブが始まらない・ファイルが無傷・普通の衝突は確認に進む・元が消えたときは断らない）。実装を 1 か所ずつ壊す変異 24 件（ガード）+ 8 件（`Application.cc`）を、すべて検出した。**罠**：(1) ディスクイメージのテストは、必ず `detach` する（デストラクタと、実行スクリプトの後始末の両方で）。(2) 読めないフォルダ（`chmod 000`）は、後始末の前に戻す。(3) `Run` の防御を外す変異は、ガードを通らずに直接 `Start` するテストでだけ検出できる（アプリ全体のテストは、開始前の確認で止まる）。(4) macOS には `timeout` コマンドが無い（暴走するかもしれない調査は、`perl -e 'alarm 60; exec @ARGV'` で包む）
### コピーの中身（自前の再帰 + `copyfile(3)`）

- **未確認（実機）**：クラウドストレージ（Dropbox などの File Provider）や SMB ボリュームへの、拡張属性つきのコピー（`COPYFILE_ALL` が、拡張属性を受け付けない先で、失敗しないか。Finder は同じことをしている）、ACL つきのファイル、`COPYFILE_CLONE` が、クローンできない先で、確実に普通のコピーに戻ること（別の APFS ボリューム = ディスクイメージでは確認済み）

UBSan と ThreadSanitizer のどちらでも通る）：`pl_copy_file` の直接（通常のファイルの更新日時（ナノ秒）・権限・拡張属性・空・バイナリ・日本語、`EEXIST`、置き換え（新しい実体・読み取り専用の先・別のハードリンク・リンクの先・フォルダの先は `EISDIR` で無傷）、**置き換えの原子性（`pl_replace_atomic`: 元が読めない・元が無い・先のフォルダに書けない・容量が足りない、のどれでも、先が無傷で、一時ファイルが残らない）、一時ファイルの名前が使われていたとき（`pl_replace_temp_collision`: ほかのものの一時ファイル 400 個を消さずに、やり直す）、容量が足りないとき（`pl_enospc`: 12 MiB を 3 MiB 個・5000 個・**`std::filesystem::copy` との比較（ランダムなツリー 150 `file_op_test` / `file_guard_test` も、`osx.mm` をリンクするようにした（`FileOperation.cc` が `pl_copy_file` を呼ぶため）。アプリ全体の `ops_test` にも、`copy_fidelity`（実物の流れで、更新日時・リンク・フォルダの更新日時）と `conflict_dangling_link`（壊れたリンクが同名のとき、上書きの確認が出る）を足した。**実装を 1 か所ずつ壊す変異 65 件（`mutate_engine.py`。`FileOperation.cc` と `osx.mm`）のうち、検出できなかったのは 11 件。どれも、理由がある**：(a) `e_attr_error_dropped`（フォルダの属性を写す失敗を無視する）：属性だけが失敗する状況を、作れない（untested の防御）。(b) `e_move_collision_allowed` / `e_move_overwrite_true` / `e_skip_regardless_of_policy`：別のボリュームへの移動のコピーで、先に同名があるのは、同時にほかが作ったときだけ（`ExistsNoFollow` の見方をそろえた後は、順番に動く限り、先は無い）。`Skip` でないのに `EEXIST` が返るのも、同じレースだけ。レースでしか効かない防御。(c) `o_no_nofollow` / `o_data_only`：`COPYFILE_CLONE` を付けると、別のボリュームへのコピーでも、`ALL` や `NOFOLLOW_SRC` が無くても、更新日時・拡張属性が写り、リンクがリンクのままになる（実測、macOS 27.0。`CLONE` を外した `ALL|EXCL` だと、リンクをたどる）。**明示したフラグは、OS の実装に頼らないための冗長**で、残した。(d) `o_dir_attr_all`：フォルダに `COPYFILE_DATA` を足しても、同じ（`copyfile` はフォルダの中身を写さない）。(e) `o_errno_after_free` / `o_errno_zero_ok`：errno の退避を、free の後に入れ替えても、変わらない（free が書き換えるかは、未確認の防御）。`copyfile` が -1 を返して errno が 0、という状況は、作れない。(f) `o_replace_temp_not_removed`：失敗した置き換えの一時ファイルを `unlink` しなくても、`copyfile` が作りかけを消すので、残らない（実測。`unlink` は、念のための二重の防御）。(g) `o_progress_any_stage`：進捗のコールバックの `stage == COPYFILE_PROGRESS` の絞りを外しても、変わらない（`copyfile` は、データのコピーでは、`PROGRESS` でしか呼ばない。12 MiB + 777 バイトで 13 回、すべて単調増加=START / FINISH は来ない）。この 2 つ（f・g）は、レビューで足した機構（原子的な置き換え・進捗）の防御で、実装を単純にするなら削れる。**レビューで見つけた 2 `o_replace_temp_removed_on_collision` / `o_replace_rename_leaves_temp`（原子的な置き換えの各部）。**罠**：(1) 読み取り専用のファイル（`0444`）は、`ofstream` で書き換えられない：先に `chmod`。(2) `0555` / `0000` のフォルダが残っていると、`remove_all` が失敗する：消す前に `chmod -R u+rwx` と `chflags nouchg`（`ForceRemove`）。(3) UNIX ドメインソケットの `sun_path` は 104 バイトまでなので、そのフォルダへ `chdir` して、短い名前で作る。(4) `std::filesystem::copy` との比較は、同名で種類が食い違うツリーを入れない（意図して変えた振る舞いなので）。(5) ディスクイメージは、必ず `detach` する（デストラクタと、実行スクリプトの後始末の両方）。(6) クローンかどうかは、時間ではなく、物理位置で見る（時間は、環境で揺れる）

## Lua の部品への分離（`copy_to` / `move_to` / `check_transfer`。2026-10-10）で変わったテスト

- 全アプリのテスト `ops_test` は、`Miata.command.copy_marked()` / `move_marked()` / `delete_marked()` を直接呼ぶ形から、**実際のキー入力（`c` `m` `dd`）で駆動する形**に直した（旧実装でも新実装でも通る。特性テスト）。`Application::StartFileOperation` は無くなり、`StartTransfer` / `CheckTransfer`。始める前の断りのテスト（`guard_*`）は、断りのダイアログが `ConfirmDialog` であること（上書きの確認の `YesNoDialog` ではない）を、そのまま確かめる（`c` / `m` は、`check_transfer` が `false` のとき、`dialog_confirm` で知らせて終わる）
- エンジンのテスト（`file_op_test` / `file_guard_test` / `copy_engine_test`）は、`FileOperationManager::Start(type, sources, dest_dir, overwrite)` の新しい署名に直しただけ（`src_dir` とモデルのポインタを渡さなくなった）。`FileOperationCompleted` の `src_model` / `dest_model` / `src_dir` は無い（完了後に更新するペインは、パスで引く）
- 新しい断る組み合わせの検査（名前の重なり・名前の無い対象・末尾の `/`）：アプリ全体 `check_transfer_duplicates` / `check_transfer_no_name` / `transfer_trailing_slash` と、エンジン（`Run` の多重の防御）`file_op_test` の `duplicate_names`。詳細な記録は `.claude/notes/lua-commands.md` の「ファイルの操作（部品と組み立て）」
