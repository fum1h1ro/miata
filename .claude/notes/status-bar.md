## 罠（テストの組み立て）

- **`mark_all` の既定の `kind` は `files`**（フォルダは入らない）。フォルダも数えたいテストは `{ kind = 'all' }`
- **`makeFirstResponder:` は、画面に出していないウィンドウでは、`acceptsFirstResponder` が NO のビューでも YES を返した**（既存のブラウザのコンテナも同じ）。クリックの検査は、`NSEvent` のマウスダウン・アップを `sendEvent:` で送って、first responder が動かないことを見る
- **`Tick()` は、各ペインの `stale_` を落とす**（ディレクトリ監視による自動リロードが、一覧の世代を動かして、関数の呼び出し回数の検査を乱さないため）
- Lua から、ダイアログを開く関数（`dialog_*`）は、コルーチンの中で呼ぶ（`Lua()` のハーネスの関数から呼ぶと、yield のエラー）。キーに束縛した関数（`<f6>`）を `PressKey` で呼ぶ
- ハーネスの関数名 `FileInfo` は、Carbon の型と衝突する（`MakeInfo` にした）
- **変異テストの worker は、最後の変異を戻した後に `make` しない**。次の起動のベースラインが、前回の最後の変異のオブジェクトに当たる（`mutate.py` は、ベースラインの前に `make` する）
- **複製に作業ツリーを `rsync` し直すと、前回の変異のオブジェクトが残る**: `rsync -a` は、元の（古い）更新時刻を保つので、変異を戻して touch したファイルが、同期で古い時刻に戻り、`make` が作り直さない（ベースラインが、前回の最後の変異で失敗する。`O02_ctime` で、更新日時が作成時刻になった）。同期の後に、ソースを全部 `touch` して、全部作り直させる（`mut_setup.sh`）
- 変異の「元の文字列」が、リファクタで、無くなる（`SKIP`）ことに注意。コンパイルできない変異（`else if (false)` が、`c` を宣言していた条件を消す）は、`BUILD-FAIL` になる（変異は、コンパイルできる形で書く）
- ゴミ箱は、`-[NSFileManager trashItemAtURL:resultingItemURL:error:]`（`object_getClass([NSFileManager defaultManager])` のメソッド）を差し替える（実物のゴミ箱に触れない）。`pending_marks` の `dd` が、確認ダイアログを閉じるだけでも、念のため
- Osaka 20pt・実機と同じ見た目は、`render_osaka`（`set_font("Osaka")` + `set_font_size(20)` の init.lua）の PNG を、目で確かめる（バーの縦位置・右の要約・長い左の切り詰め）

## 実機未確認

- 実機のキー入力: 前置き（`g` の後など）の途中の見え方、IME がオンのときのキー（コードは物理位置）、Caps Lock、キーリピート（`g` 長押し）、Option+キー
- Retina の実画面での見た目（PNG は、オフスクリーンの描画）
- 更新のタイマー（default モードだけ）が止まる間（メニューを開いている・ウィンドウのライブリサイズ中）の、バーの更新（止まるはず。コピーの進捗パネルと同じ）
- ダウンロード前のファイル（`<CLOUD>`）と、Finder のエイリアス（`<ALIAS>`）のバーの表示（純ロジックの書式だけ確かめた。実物のファイルは、実機のクラウドが要る）
- ネットワークボリューム（SMB など）で、カーソルのたびの `lstat` と、マークの合計の `stat` が、操作を止めないか
- VoiceOver の読み上げ（`NSAccessibilityStaticTextRole`。バーの全体を、1 つの文字列として読む）
- フォルダの属性（`~/Library` など、`UF_HIDDEN` のフラグ）の表示。外部で属性が変わったとき（自動リロードは、監視で拾う）
