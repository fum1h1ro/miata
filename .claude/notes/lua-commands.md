- **経緯：最初の実装は、安全でなかった**。パスを `'…'` でクォートして、コマンドラインに埋め込んでいた。ユーザーが持ち込んだ別のレビューの指摘（2026-10-12）で、`"%f"` と書くと、細工した名前の `$(…)` が実行されることを、展開結果を `/bin/sh -c` で実際に動かして確かめた（`'%f'`・`\%f` も、名前によっては同じ）。**最初のテスト（引数の行列など。変異テストは途中）は、全部通っていた**: `%f` を引用符に入れる使い方を、テストしていなかった。位置パラメータに変え（`injection` を足し、引用符の検査を足した）、変異テストをやり直した。教訓: **「利用者が書く側（テンプレート）の書き方の違い」も、入力の軸として、テストの行列に入れる**。名前の側だけを振っても、テンプレートの側の落とし穴は、見つからない
- **罠**：(1) ハーネスの PATH に Homebrew が入っていると、「PATH を足す」実装が、壊れていても通る：Finder 起動と同じ最小の PATH（`/usr/bin:/bin:/usr/sbin:/sbin`）にして、先頭に偽の `open` を置く（既定の `open -t %f` が、本物の `open` で TextEdit などを開いてしまわないためでもある）。(2) 一時ファイルの置き場を共有すると、残す変異（`unlink` 抜き）が後の実行を汚して、偽の検出になり、ユーザーの `TMPDIR` にも残る：`TMPDIR` は、シナリオごとに新しくする。(3) ファイル名に `/` は入れられないので、`$(touch …)` を含む実在のファイルは、相対パス（`touch PWNED`）にして、ハーネスの作業ディレクトリを記録の置き場にする。(4) 子の標準入出力を `lsof` で調べるスクリプトは、リダイレクトの内側で測ると、出力ファイルが見える（外で測る）。(5) `glob_t` は、`-fobjc-arc` では、既定のコンストラクタが削除される（`std::filesystem::directory_iterator` で数える）。(6) `SIGPIPE` の無視の引き継ぎは、子が `perl -e 'print $SIG{PIPE}'` で見るまで分からない（ハーネス自身を `signal(SIGPIPE, SIG_IGN)` にしておく）。(7) 複数回書くスクリプト（ループ）は、同じ記録ファイルに後から書き足して、次のスクリプトの記録を汚す：スクリプトごとに、別のタグ。(8) 位置パラメータのテストで、「パス」に使う文字列も、絶対パスでなければならない（`paths` の検査）。感度の確認（`eval "$1"`）は、`/;touch …;#` のような、絶対パスの形のシェルのコード。(9) 置換パターンが複数か所に一致する変異は、`BAD_PATTERN` になって走らない（`a09`: `open_paths` に同じ並びがある）：前後の文脈を入れる。(10) 掃引の間は、プロセスの起動や一時ファイルを数えるテストを、並行して走らせない（時間の検査・数える検査が、偽の検出になる）
- **実測**：`ARG_MAX` = 1048576。3000 件（200 KB ほど）は通り、約 1.2 MB（パス 12000 件ほど）は `posix_spawn` が `E2BIG`（`Argument list too long`）で失敗する。位置パラメータで渡す分も、同じ上限に入る。本物の `open -t 存在しないファイル` は `The file … does not exist.`、`open -a 存在しないアプリ 存在するファイル` は `Unable to find application named '…'`（どちらも終了コード 1。ウィンドウは開かない）。子の標準エラーの一時ファイルは、`lsof` では `/private/var/folders/…/T/miata-spawn-XXXXXX`（名前を消してあっても、パスが見える）
