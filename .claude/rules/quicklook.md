## プレビュー（Quick Look）

`Miata.command.quick_look([pane])` → `Application::lua_command_quick_look` → `View::ToggleQuickLook` → `BrowserView::ToggleQuickLook`。カーソル下のファイルを `QLPreviewView`（QuickLookUI）で、一覧の上に被せて表示する。別ウィンドウの `QLPreviewPanel`（旧 `pl_quick_preview`）は使わない（パネルはウィンドウで、ビューにできないため。旧実装は削除済み）。

- **構造**：`BrowserView::NativeView()` は `_MiataBrowserContainer`（`BrowserView.mm`）で、`NSSplitView`（左右ペイン）と、その上に重ねる覆い（`QuickLookView::NativeView()` = `_MiataQuickLookShield`）、各ペインの下の入力バー（後述「ファイル名の検索」「絞り込み（フィルタ）」。左右 × 検索・絞り込みの4つ。覆いより手前に重なる）を子に持つ。覆いの中に `QLPreviewView` を入れる。覆いの位置は、範囲（`constants::QuickLookArea` = `Both`/`Left`/`Right`）に応じてペインの frame から決め、**`NSSplitView` のデリゲート（`splitViewDidResizeSubviews:`）で追従**する（ウィンドウのリサイズもディバイダのドラッグもここに来る）。覆いは不透明に塗る（読み込み中や空のとき、下の一覧が透けないように）。色は一覧と同じ設定の背景色（`Config::Background()`。後述「色の設定」）。
- **範囲と「何を見せるか」は別**：見せるのは常に「カーソルのあるペインのカーソル下のファイル」で、範囲は被せる場所だけを決める。Lua には `"both"`/`"left"`/`"right"`（省略・nil は both）で公開し、変換は `Application.cc` の `ParseQuickLookArea()`（`ParsePane()` に `"both"` を足したもの）に集約している。`ToggleQuickLook(area)` は、同じ範囲なら閉じ、別の範囲なら範囲だけ切り替える（`QLPreviewView` は作り直さない）。`Navigate::Cancel`（Esc）でも閉じる。
- **追従はティック駆動**：カーソル下のファイルは、カーソル移動・ペイン切替・ディレクトリ移動・再読み込み・ソートなど多くの経路で変わり、通知点が 1 つに揃っていない。通知を集めず、`Application::Update()` → `BrowserView::UpdateQuickLook()` が毎ティック `FileListView::CurrentPath()` を見て、直近の値（`quick_look_target_`）とプレビューに渡した値（`quick_look_shown_`）を比べる（`UpdateAutoReload` と同じく、状態を見て判断する方式）。変わってから 0.1 秒（`kQuickLookSettleDelay`）落ち着いたら切り替える。出した時点のファイルは待たずに設定する。一覧は空になり得る（空のディレクトリ、絞り込みで0件）ので、カーソル下は `CurrentPath()`（空なら nullopt）か `CurrentOrNull()`（空なら nullptr）で読む（範囲外を読む `GetCurrent()` は削除した。後述「空のディレクトリ」）。
- **キー入力の安全（実測済み）**：`QLPreviewView` は `acceptsFirstResponder` が YES で、**クリックすると first responder を奪う**（覆い無しで確認済み）。奪われるとキー入力が `MiataRootView` に届かなくなる恐れがあるので、覆いが `hitTest:` で常に自分を返し、クリックを `QLPreviewView` に渡さない（`_MiataFileListNSView` が first responder にならないのと同じ考え方）。代償として、プレビューの中のマウス操作（PDF のスクロール、動画の再生ボタン）と、覆った範囲でのマーク済みファイルのドラッグはできない（**例外はトラックパッドのピンチとスクロール**で、プレビューの中へ届く。後述「倍率」「スクロールの転送」）。一方、`QLPreviewView` は読み込み（`previewItem` の設定）では first responder を取りに来ず（キーウィンドウでも確認済み）、`performKeyEquivalent:` も横取りしなかったので、「奪われたら戻す」処理は入れていない。
- **倍率（ズーム。`QuickLookView::Zoom` / `SetZoom`。Lua は `quick_look_zoom`）**：`QLPreviewView` 自体には、倍率を指定する手段が無い。公開 API が無く、非公開の `zoomFactor` / `setZoomFactor:` / `maxZoomFactor` / `autoZooms` / `receivedPinchGestureWithMagnification:` も、試した種類（画像・PDF・txt・xlsx）のどれでも効かない（getter は常に 1.0 で、画素も変わらない）。`displayState` は `{CurrentPage}`（PDF）/ `{CurrentScroll}`（テキスト）/ nil で、倍率のキーが無い。**中身のビューを直接触る**しかなく、その作りが**種類で違う**（macOS 27.0 で、実測）：
  - **WebKit で描かれる種類**（xlsx・docx・csv・html・svg）：`QLWeb2View`（`WKWebView` のサブクラス。アプリ内）。公開 API の `magnification`。ピンチは、`allowsMagnification` が YES なので、渡せば効く
  - **テキスト系**（txt・md・rtf）：`QLTextScrollView`（`NSScrollView`。`documentView` は `NSTextView`。アプリ内）。`magnification`（`allowsMagnification` が NO のままでも、setter は効く）。ピンチは、`allowsMagnification` が NO で受けないので、渡す前に YES にする（`AllowMagnification`）
  - **別プロセスで描かれる種類**（画像・PDF・json）：`NSRemoteView`。触る手段が無く、ズームできない（`Zoom()` は nullopt）。合成したピンチを `NSRemoteView` へ渡しても（直接・窓経由・開始/終了のジェスチャ付き）、何も起きなかった（png・pdf。本物のトラックパッドは未確認）。外側から見た目だけ拡大する方法（layer の `sublayerTransform` は、PDF がぼやける。`QLPreviewView` の frame を大きくして覆いでクリップすると、画像・PDF は鮮明だが、テキストは文字が大きくならない）は、実測したが入れていない
  - 中のビューは、`FindZoomTarget`（`QuickLookView.mm`）が、**公開の基底クラス**（`WKWebView`、`NSTextView` を持つ `NSScrollView`）で探す。非公開のクラス名には頼らない（OS が作りを変えたら、見つからない=ズームできないだけで、壊れない）。`WebKit.framework` をリンクする（`CMakeLists.txt`）
  - `SetZoom` は、`kMinZoom`〜`kMaxZoom`（0.25〜4.0）に丸めて、**読み戻した倍率**を返す（読み戻しは遅れない=直後に読んで、×1.25 を繰り返しても積み上がる）。表示していない・読み込み中（中のビューがまだ無い）・ズームできない種類のときは、どちらも nullopt。**倍率は中のビューだけが持つ**（`QuickLookView` は持たない）ので、ピンチとコマンドが食い違わない。Lua の `"in"` / `"out"`（×1.25・÷1.25）と `"reset"` は、`Application.cc` の `lua_command_quick_look_zoom` が、`Zoom()` を読んで `SetZoom()` する（`luaL_error` の前に、デストラクタを持つオブジェクトを作らない）
  - **ピンチの上限・下限は、中のビュー自身のもの**（`SetZoom` の丸めを通らない）。実測では、WebKit 系は 1.0〜3.0、テキスト系は 0.25〜4.0 で、どちらも `kMinZoom`〜`kMaxZoom` の内側に収まる（だから、ピンチで広げた後に `"in"` を押して縮む、という逆転は起きない）。`SetZoom` は、WebKit 系にも 0.25〜4.0 まで指定できる（ピンチより広い）。中のビューの範囲が `kMinZoom`〜`kMaxZoom` の外へ広がったら、`SetZoom` の丸めを、今の倍率を含めて広げること
  - **ファイルを切り替えると 100% に戻る**：QuickLookUI が、中のビューを作り直す・倍率を戻すので、こちらでは何もしていない（xlsx → xlsx・docx、txt → md で確認。明示のリセットは要らなかった）
- **ピンチの転送（`_MiataQuickLookShield`）**：覆いの `hitTest:` が常に自分を返すので、トラックパッドのピンチ（`magnifyWithEvent:`）は覆いに届く（窓経由で合成したイベントが、全部覆いに着くことを確かめた）。以前は、どこも処理せずに捨てていた。いまは、覆いの `magnifyWithEvent:` が、ズームできる中のビューへ渡す（ズームできない種類は、これまで通り捨てる）。ピンチは first responder を動かさないので、覆いの存在理由（キー入力を守る）とぶつからない。**罠**：(1) `QLPreviewView` は `magnifyWithEvent:` を実装しておらず、渡しても `nextResponder`（=覆い）へ戻ってくるだけ。だから、`QLPreviewView` ではなく、中のビューへ直接渡す。(2) 中のビューが受けずに戻してきても、戻り先は覆いなので、**`forwarding_` で再入を止める**（止めないと、覆い→中のビュー→覆い…と、無限に再帰する）。(3) ピンチで渡すのは `magnifyWithEvent:` だけ（`beginGesture` / `endGesture` / `smartMagnify` は渡していない=未確認）。スクロールは、次の項目
- **スクロールの転送（`_MiataQuickLookShield`）**：スクロール（トラックパッドの 2 本指・マウスのホイール）も、覆いの `hitTest:` のせいで、覆いに届いて捨てられていた。いまは、覆いの `scrollWheel:` が、**イベントの位置にある、プレビューの中のいちばん奥のビュー**（`contentViewUnder:`。覆い自身の `hitTest:` は常に自分を返すので、`NSView` の実装（`[super hitTest:]`）を、親の座標系の点で呼ぶ）へ渡す。そこから先は、レスポンダチェーンに任せる（覆いが無ければ、AppKit がそのイベントを届けていたビュー）ので、ピンチと違って、ズームできる種類に限らない（テキストなら `QLTextView` → `NSClipView` → `QLTextScrollView`、WebKit なら `WKWebView` へ上がる）。イベントは、位相（開始・途中・終了・慣性）も含めて、そのまま渡す。first responder は動かない（xlsx・txt で、前後を確かめた）。ピンチと同じ `forwarding_` で、再入を止める（処理されずに戻ってきたとき、戻り先は覆い。外す変異を、試験が捕まえた）。**AppKit が通常やる、ジェスチャの間の送り先の固定（最初のイベントのビューへ、終わりまで送り続ける）は、していない**（イベントごとに、位置のビューを引き直す。ポインタがプレビューの外へ出ると、そこで止まる）。**画像・PDF・json（`NSRemoteView`）は、合成したスクロールでは動かなかった**（パネルをキーにしても同じ。ピンチと同じ）ので、実機の本物のイベントで動くかは未確認（届かなければ、これまで通り捨てるだけ）
- **罠（`QLPreviewView` の `close`、実測。守らないとプロセスが異常終了する）**：`close` は**ウィンドウに載っている間に、1 回だけ**呼ぶ（二重に呼ぶ・ウィンドウから外れた後に呼ぶと、QuickLook の `_QLRaiseAssert` で abort）。`close` した後のビューには**何も触らない**（`previewItem` の設定を含む）。だから `QuickLookView::Hide()` は、外す前に `close` してすぐ手放し、出すたびに `QLPreviewView` を作り直す（1 回 0.5ms 未満）。`shouldCloseWithWindow` は **NO** にする（既定の YES だと、ウィンドウを閉じるときに QuickLook 側も自動で `close` するため、その後の `Hide()` が二重 close になる。ウィンドウを閉じるとアプリは終了するが、その間もタイマーのティックは回る）。
