# Lua のコマンド（状況の取得・ファイルを開く・まとめてマーク）

> 機能別の設計メモ。上の `paths:` のファイルを触ると自動で読み込まれる。`Application.cc` など複数の機能が同居するファイルでは載らないので、そのときは CLAUDE.md の「設計メモの索引」から、該当するファイルを自分で読むこと。
> テスト・実測・実機未確認の記録は `.claude/notes/lua-commands.md`（自動では読み込まれない。テストを書く・直す・検証するときに読む）。

## Lua から状況を取る（`pane_path` / `cursor_entry` / `marked_entries` / `current_sort`）

スクリプトが、ペインの今の状況（いるフォルダ・カーソル下のエントリ・マーク済みのエントリ・ソート）を読むための 4 つのコマンド（`Application.cc` の `lua_command_pane_path` ほか）。ユーザー向けの仕様は README の「状況の取得」。ここには、設計の決定と罠を書く。以前は、Lua から取れる状況は `current_pane()`（どちらのペインか）と `history_list()` だけで、カーソル下のファイルやマークは取れなかった（`Miata._private.rename_target` が、カーソルのファイル名を返すだけ。リネーム用の内部用）。そのため、ファイルを開く・外部のコマンドに渡す、といった処理を `init.lua` で書けなかった。

- **小さな getter を 4 つ**：1 つの `pane_state()` に、全部まとめて返す形にはしなかった。マーク済みの一覧は、件数が多いと重い（数千件）ので、要るときだけ作る。どれも `pane`（`"left"` / `"right"`）を取る（`OptionalPaneArg`。省略は、カーソルのあるペイン）。`view_commands[]` に登録する（トランポリン経由なので、設定ファイルの読み込み中に呼ぶと、落ちずに Lua のエラーになる）。読むだけで、状態は変えない
- **エントリは `{ name, path, is_dir }` のテーブル**（`PushEntryTable`）：パスの文字列だけにしなかったのは、フォルダかどうかが要るため（Lua の標準ライブラリには、フォルダの判定が無い）。`size` や `mtime` は、必要になるまで出さない。`name` は画面に出る名前（`Name()`。NFC で、UTF-8 として不正なバイトは U+FFFD に置き換え済み）、`path` は元のバイト列のパス（`Path()`）：NFD で保存された名前（`e` + 結合アクサン）や、UTF-8 として不正な名前では、2 つの綴りが違う。パスの操作に渡すのは `path`（`name` を足してパスを作ると、そのファイルを指さないことがある。「名前が UTF-8 として不正なファイル」と同じ理由）。`is_dir` は `IsDirectory()` で、シンボリックリンクをたどる（Enter で入れるか、と同じ）。壊れたリンクは `false`（落ちない）
- **`marked_entries` は、マークが無ければ空の配列**（カーソル下の 1 件にしない）。絞り込み中は、見えているマークだけ（隠れた行のマークは含まない）：コピー・移動（`StartFileOperation`）は、マークが無ければカーソル下の 1 件を対象にする（ゴミ箱の `DeleteMarked` は、マークが無ければ何もしない）が、getter は素直に「マーク済み」を返す。「操作の対象」（マーク済み、無ければカーソル下）を返す関数（`target_entries`）は、足していない（ユーザーの判断：使い方が見えてから）。README の例が、`marked_entries` と `cursor_entry` を組み合わせる形を示している。`open` などのコマンドも、対象はいつも明示する（後述「ファイルを開く」）
- **並びは画面の表示順**（`FileListView::MarkedEntries()`：`list_` の順）。ソートに従い、マークした順でも、モデルの走査順でもない。ドラッグ（`BeginDrag`）と共用する（以前は `BeginDrag` の中に同じループがあった）。コピー・移動（`StartFileOperation`）・ゴミ箱（`DeleteMarked`）も、同じ `MarkedEntries()` で対象を集める（以前は、モデルの走査順で集めていた）
- **`cursor_entry` は `CurrentOrNull()`**（一覧が空なら `nullptr` → Lua の `nil`）。（範囲外を読む `GetCurrent()` は削除した。後述「空のディレクトリ」）
- **`current_sort` は `key, reverse` の 2 つの値**：`key` は `FileListView::SortKeyName`（Lua の `sort` の引数と、ペインの状態の保存で、同じ名前）。`sort(current_sort())` は何も変えない。`sort` はフォーカスのあるペインだけに効くので、反対側のペインの `current_sort("right")` を `sort` に渡すと、フォーカスのあるペインが変わる（対称ではない。`sort` にペイン引数を足すのは別件）。`resources/test.lua` の `s` が、これで今のソートから始まる（基準の行にカーソルがあり、降順ならチェックが入っている）。行を選ぶと、降順のチェックは今の状態のまま引き継がれる（以前は、いつも昇順に戻った）
- **値は呼んだ時点の写し**：`FileEntryModel*` などのポインタを、Lua に渡さない（再スキャンで旧エントリが破棄される）。`PushEntryTable` は、Lua の C API と `std::string` だけを使う。`luaL_error`（longjmp）の前に、デストラクタを持つオブジェクトを作らない：`OptionalPaneArg` を最初に呼ぶ（エラーを起こすのはここだけ）。その後に作る `std::string` や `vector` は、メモリ不足のエラー（`lua_createtable` など）が起きたときにだけ漏れる（`history_list` と同じ）
- **罠：このビルドの Lua は `io.popen` が使えない**（`'popen' not supported`）：`packages/CMakeLists.txt` が、`LUA_USE_POSIX` / `LUA_USE_MACOSX` を定義せずに、`lua/*.c` をそのままビルドしているため。外部のコマンドの出力を取るには、`os.execute` でファイルにリダイレクトして、`io.open` で読む。有効にするなら `target_compile_definitions(lua PRIVATE LUA_USE_MACOSX)` だが、`os.tmpname` などの挙動も変わるので、別件として確かめてから。`os.execute` は終わるまで Miata が止まる（README の例は、`&` で待たない）

## ファイルを開く（`open` / `open_with` / `reveal` / `copy_path` / `set_clipboard`）

ファイルを既定のアプリで開く、アプリを指定して開く、Finder で表示する、パスをクリップボードに置く、ための 5 つのコマンドと、一覧の Enter でファイルを開く既定のキー。ユーザー向けの仕様は README の「ファイルを開く」。ここには、設計の決定と罠を書く。以前は、ファイルを開く手段が無く（Enter はフォルダに入るだけ）、`os.execute("open …")` を `init.lua` に書くしかなかった（シェルを通るのでクォートが要り、終わるまで Miata が止まる）。

- **層の分け方**：OS 依存は `platform.h` の `pl_find_application` / `pl_open_paths` / `pl_reveal_paths` / `pl_set_clipboard_text`（`osx.mm`。`NSWorkspace` と `NSPasteboard`）。`Application.cc` が Lua とのつなぎ：`Miata._private.paths_of`（対象の検証と正規化）・`open_paths`・`reveal_paths`と、`Miata.command.set_clipboard`。公開の `open` / `open_with` / `reveal` / `copy_path` は、`base.lua` の Lua 関数：確認のダイアログ（`dialog_yes_no`）を待つ必要があり、それはコルーチンの Lua からしか書けないため。Lua のラッパーと C++ のコマンドは、名前を分けた（同名だと、C++ が Lua を無言で上書きする。「C++ から Lua へ関数を登録する手順」）
- **対象は、いつも明示する**（ユーザーの判断）：`target` は、パスの文字列、エントリ（`{ path = 文字列 }`。`cursor_entry` の戻り値など）、またはその配列。「マーク済み、無ければカーソル下」を返す関数は、足していない（`marked_entries` と `cursor_entry` を、呼ぶ側で組み合わせる。README の例と `test.lua` の `targets()`）。`paths_of` が、全コマンドの入口で、絶対パスの文字列の配列にする：`path` を持つ表はエントリ（配列として読まない。`path` が文字列でなければエラー）、持たない表は配列（要素は文字列かエントリ。入れ子はエラー）。絶対パスは、`/` で始まり、NUL を含まないこと（`..` や `//` は通す：`jump_to` と違い、開くだけなので）。`nil`・相対パス・空の文字列はエラー（相対パスは、起動した場所で意味が変わる）。Lua の C API だけで書いてあり、エラー（longjmp）の前にデストラクタを持つオブジェクトが無い。`open_paths` / `reveal_paths` は、`paths_of` の結果（空でない配列）だけを受け取り、空はエラー（空のとき何もしないのは、Lua のラッパー。2 つの層で、同じ検査を重ねない）
- **シェルを通らない**：`NSWorkspace` を直接呼ぶので、クォートの問題が無い。パスは `fileURLWithFileSystemRepresentation:` で、バイト列のままの URL にする（UTF-8 として不正な名前でも、NSString を経由しないので例外にならない。ドラッグ・Quick Look と同じ）。NFD の名前（`e` + 結合アクサン）も、`path` のまま渡る
- **非同期**：`openURL:configuration:completionHandler:` / `openURLs:withApplicationAtURL:…` の完了ハンドラは、別のキューで呼ばれる。失敗は、メインスレッドに戻してから、`View::ReportFileError` でダイアログにする。既定のアプリで開くときは、ファイルごとに 1 回呼ぶので、`dispatch_group` で全部の結果を待ち、失敗を 1 回のダイアログにまとめる（「N件が開けませんでした (M件中): OSの説明」。1 件だけ渡して失敗したときは「開けませんでした: OSの説明」）。アプリを指定した要求は、まとめて 1 回なので、失敗したら全部が開けなかったことになる。権限の案内（フルディスクアクセス）は付けない：開けなかったのは、Miata の権限の問題ではない（`FileError::permission_denied` は false）。Lua の戻り値は「要求を出せたか」で、開けたかではない。OS の説明は、アプリがローカライズされていないので、英語で出ると思われる（未確認）
- **アプリの指定**（`pl_find_application`）：絶対パス（フォルダとして存在すればよい。アプリかは問わない）→ Bundle ID（ドットを含むとき。`URLForApplicationWithBundleIdentifier:`）→ 名前（`~/Applications`、`/Applications`、`/Applications/Utilities`、`/System/Applications`、`/System/Applications/Utilities`、`/System/Library/CoreServices` の順に、`<名前>.app` を、大文字小文字を区別せず探す）。名前の検索に `fullPathForApplication:` を使わなかったのは、macOS 11 で非推奨だから。ほかの場所のアプリ（Homebrew の cask など）は、名前では見つからない（Bundle ID か絶対パス）。見つからなければ、要求を出さずに、ダイアログで知らせて `false`
- **多数を開くときの確認**（`base.lua` の `OPEN_CONFIRM_LIMIT` = 10）：`open` / `open_with` で、10 件を超えると `dialog_yes_no`（既定は「いいえ」）。全マークなどで、何百ものウィンドウを開かないため。`reveal` / `copy_path` は確認しない（ウィンドウを増やさない）。ダイアログを待つので、キーに割り当てた関数（コルーチン）の中から呼ぶ。10 件までなら yield しないので、どこからでも呼べる。ラベルに `&x`（ショートカット）は付けていない（うっかり押したキーで確定しないため）
- **Enter**（`test.lua`）：`"nd"` の 1 つだった束縛を、ダイアログ用（`"d"`: `navigate_ok`）と一覧用（`"n"`）に分けた。一覧の Enter は、カーソルのエントリがフォルダ（シンボリックリンクはたどる）なら `navigate_ok`、ファイルなら `open`。`.app` などのパッケージは、`is_dir` が true なのでフォルダとして入る（起動するには `o`）。一覧が空なら `navigate_ok`（何も起きない）。**`"nd"` のままにすると、ダイアログの後ろのカーソルがファイルのとき、Enter がダイアログを閉じる代わりにファイルを開いてしまう**ので、モードを分ける。`navigate_ok` 自体は、これまでどおり（C++ は変えていない）。`o` / `<S-o>` / `yy` も `test.lua`（`targets()` を使う）
- **クリップボード**（`pl_set_clipboard_text`）：`clearContents` してから文字列を置く（前の別の形式のデータ=古い画像などが残ると、貼り付けで混ざる。テストは、別の形式のデータを置いて確かめる）。UTF-8 として不正なバイトは `RepairUtf8` で U+FFFD にする（NSString にできないため）。NUL を含んでもよい（`c_str()` ではなく長さで NSString にする）。`copy_path` は、パスを改行でつなぐ（末尾に改行は付かない）
- **限界**：Enter でファイルを開く動作は、拡張子ごとの切り替え（AFXW の拡張子判別実行）を持たない（README の例のように、`init.lua` で書く）。`open_with` の「アプリを選ぶ」ダイアログは無い。名前で見つからないアプリは、Bundle ID か絶対パス。開いたアプリが前面に出るので、Miata は背面に回る

## まとめてマークする（`mark_all` / `unmark_all` / `invert_marks` / `mark_range` / `mark_search_hits` / `next_mark` / `prev_mark`）

ペインの複数の行をまとめてマークする 5 つのコマンドと、マーク済みの行へカーソルを動かす 2 つのコマンド。ユーザー向けの仕様は README の「まとめてマークする」。ここには、設計の決定と罠を書く。以前は、マークは `mark` / `unmark` / `toggle_mark` の、カーソル下の 1 件だけで、まとめて操作する手段が無かった（AFXW の `A`（反転）・`Ctrl+Space`（範囲）・検索中の `Ctrl+Space`・`Ctrl+:`（マークへ移動）に当たる）。**キーバインドは付けていない**（ユーザーの判断。後で決める）。`resources/test.lua` は変えていない。

- **層**：数え上げと変更は `FileListView`。`MarkAll` / `MarkRange` / `MarkSearchHits` は、共通の `MarkRows(mode, kind, in_scope)` に、行の条件（全部・範囲・検索のヒット）だけを渡す（`kind` の判定・`matched` / `changed` の数え方・描き直しが 1 か所）。`StepMark` は別。`ApplyMarkMode` と `MarkKindMatches` は `.mm` の先頭の無名名前空間。Lua とのつなぎは `Application.cc`（`ReadMarkOpts` ほか）。`View` には足していない（`marked_entries` と同じく、`app.view_->GetFileListView(pane)` を直接呼ぶ）。モデル（`FileListModel`）には足していない：モデルの `Mark()` はビューに通知しない（前述「一覧の再読み込み」）ので、マークを変えて描き直すところまでが、ビューの仕事。全て C++ のコマンドで、`view_commands[]` に登録する（`base.lua` に同名は無い。設定の読み込み中に呼ばれたら、トランポリンがエラーにする）
- **対象は「画面に出ている行」（`list_`）で、モデルの全エントリ（`entries_`）ではない**：絞り込み（後述「絞り込み（フィルタ）」）をしていると、`list_` は絞り込み後の行だけなので、「絞り込んでから全マーク」ができる（パターンマーク（AFXW の `@`）の代わり）。隠れた行のマークは、変えない。絞り込みを足すときに決めたこと（ユーザーの判断）：(1) `copy_marked` / `move_marked` / `delete_marked` / リネームの対象は、**見えているマークだけ**（隠れたマークは残るが、対象にならない）。(2) `unmark_all` は、見えている行だけ外す（隠れたマークを外すには、`filter_clear()` してから）。(3) `MarkedEntries()` / `marked_entries` / ドラッグは、見えているマークだけ。(4) 再読み込みは、マークをモデルのエントリで引き継ぐので、隠れたマークも残る
- **パターンでマーク（AFXW の `@`）と同名比較マーク（`W`）は、足していない**（ユーザーの判断。前者は、絞り込み（`filter_set`）で代わりにする。後者は、足す範囲として選ばれなかった）。足すなら、ワイルドカードは `*` と `?` だけで、`[` は文字として扱う方が、AFXW と、`[SubGroup] 名前` のような名前に合う、と考えていた（未実装）
- **戻り値は `matched, changed`（2 つの整数）**：`matched` は、対象になった行の数（`kind` に合う行、範囲の行、ヒットの行）、`changed` は、そのうち、マークの状態が実際に変わった数。1 つだけだと、「対象が無い」と「もうマークしてあった」を区別できない（スクリプトが「合うものがありません」と知らせたいとき）。`mark_range` の起点が無いときは `0, 0`。`unmark_all` の `matched` は、マークが無くても、対象の行数になる（`kind` に合う行）
- **`kind` の既定が、コマンドごとに違う**：`mark_all` と `invert_marks` は `"files"`（ユーザーの判断。AFXW の `A` がファイルだけで、`Shift+A` でフォルダも）、`unmark_all` は `"all"`（全解除が、フォルダのマークを残すと驚く。ユーザーには確かめていない、私の判断）、`mark_search_hits` は `"all"`（強調されている行は全部、が見た目どおり。`"files"` にすると、フォルダ名で探したときに何もマークされない。これも私の判断）。`mark_range` は `kind` を取らず、間の行を全部（フォルダも）マークする（見た目の範囲を、そのままマークするため）。フォルダかどうかは `IsDirectory()`（Lua の `is_dir` と同じ。リンクはたどる。壊れたリンクはフォルダではない）
- **`mode` は `mark_search_hits` だけ**：`mark_all` / `unmark_all` / `invert_marks` は、それぞれ mark / unmark / toggle に決まっていて、`mode` を取ると冗長。`mark_search_hits` だけは、「ヒットを外す」「反転する」に別の名前を作らないため
- **opts は厳格（知らない項目・このコマンドが許さない項目はエラー）**：既定が結果を左右する（`kind` のつづりを間違えて黙って無視されると、フォルダがマークされ、`delete_marked` で消される）。`ReadMarkOpts(L, index, slots)`：`lua_next` で 1 回走査し（raw。メタテーブルの `__index` は呼ばれない）、名前ごとに、置き場（`MarkOptSlots`）へ読む。各コマンドは、**ローカル変数に省略したときの値を入れて、その置き場を渡し、読んだ後の値を使う**（`pane` は全コマンドが使えるので参照、`kind` / `mode` / `from` は、そのコマンドが許すときだけ非 null のポインタ。許さない名前と、知らない名前は、同じ `else` で「unknown option」）。最初は、構造体 + 許す項目のビット + 名前→ビットの表 + 2 回の走査（先に検査、次に `lua_rawget`）だったが、レビューで、この形に単純にした。文字列でない名前は、`lua_tostring` が数値のキーを文字列に変えて、`lua_next` を壊すので、型を先に見る。値は `ReadMarkOptValue<T>`（文字列でなければエラー。`ParseMark…` が `std::optional<列挙型>` を返す）。**`luaL_error`（longjmp）の前に、デストラクタを持つオブジェクトを作らない**：置き場とローカル変数は、列挙型と、参照・ポインタだけ。余分な引数（opts の後ろ）は無視する。1 つの opts に誤りが複数あるとき、先に出るメッセージは走査順（決まっていない）になる：テストは、誤りが 1 つのケースだけにする
- **描き直しは、マークが変わったときだけ**（`MarkRows` の `changed > 0`。`next_mark` / `prev_mark` は、カーソルを動かしたとき=`JumpCursorTo`）：変わらない呼び出しで `Redraw()` すると、スクロールがカーソルへ戻る（フォーカスのあるペイン）。`Redraw()` は 1 回（行ごとに呼ばない。5005 行でも 1〜3 回）。テストは、`_MiataFileListNSView` の `setNeedsDisplay:` を数える
- **ダイアログの表示中でも動く**（`IsAnyDialogOpened()` で止めない）：`dialog_*` を閉じた直後のティックで呼ばれる（`jump_to` と同じ。前述「フォルダの履歴」）
- **`mark_range`**：起点は「カーソルの行を含まず、`from` の向きでいちばん近いマーク済みの行」。カーソルの行がマーク済みでも、起点にしない（そうすると、カーソルの行だけがマークされて、何も起きない）。起点が無ければ、何もしない（先頭や末尾までは、マークしない：うっかり押したときに、広い範囲がマークされないように。AFXW の挙動は、文書に無く、確かめていない）。カーソルは動かさない。範囲の行は `MarkMode::Mark`（反転ではない：起点のマークを外さない）で、`kind` は見ない（フォルダも）。**カーソルを丸める処理は置いていない**：`cursorIndex_` は、書くたびに `Redraw()` が丸める（`SetCursor` / `MoveCursor` / 購読 / `JumpCursorTo`）ので、Lua から呼ばれる時点で、一覧が空でなければ範囲内。空のときだけ 0 のまま範囲外だが、探索のループ（`row >= 0 && row < size`）も、`StepMark` の `k < size` も回らないので、空の判定は要らない。最初は `ClampedCursor()` を作ったが、「範囲外になりうる」という前提が事実でなかった（レビューで指摘）ので削除した。**`std::clamp(c, 0, size - 1)` は、一覧が空だと未定義動作**（下限より上限が小さい）なので使わない。起きない状態（`#define private public` で `cursorIndex_` に 999 を書く）のテストは書かない
- **`mark_search_hits`**：`search_.RangesFor(row)` が非 null の行がヒット。検索していない（Idle）ときのヒットは空（`SearchState::Clear` が空にする）なので、モードを見ない（見ても、冗長な検査になる）。入力中（Typing）も確定後（Committed）も同じ。ヒットは `Fetch()` のたびに作り直される（前述「ファイル名の検索」）ので、並べ替え・再読み込みに追従する。検索を終わらせない
- **`next_mark` / `prev_mark`**：`StepMark(dir)`。カーソルの行を除く全ての行（`size - 1` 行）を、向きに沿って一周して探す（`(cursorIndex_ + step * k + size) % size`：`cursorIndex_` は 0 以上なので、`size` を足せば負にならない）。見つかったら `JumpCursorTo(row)`（画面の外なら、中央に出す。検索の `n` / `N` と同じ。フォーカスの無いペインは、スクロールしない）。表示順（`list_`）で動く（モデルの走査順ではない）。動けなければ `false` で、**ビープは鳴らさない**（`search_next` は鳴らす。ビープはハーネスで止められず、テストの間、鳴ってしまう。戻り値で知らせる）
