# コマンドの実行（`shell` / `x`。出力はコンソールへ）

> 機能別の設計メモ。上の `paths:` のファイルを触ると自動で読み込まれる。`Application.cc`・`osx.mm`・`base.lua`・`test.lua` など複数の機能が同居するファイルでは載らないので、そのときは CLAUDE.md の「設計メモの索引」から、該当するファイルを自分で読むこと。
> テスト・実測・実機未確認の記録は `.claude/notes/shell-command.md`（自動では読み込まれない。テストを書く・直す・検証するときに読む）。

カーソル下のファイルで `x` → コマンドラインの入力欄（初めの値はそのファイルの名前、キャレットは名前の前。OK / キャンセル）→ そのファイルのあるフォルダを作業フォルダにして、入力した 1 行を実行する（2026-11-11。AFXW の `X`）。出力は、コンソールに流す。ユーザー向けの仕様は README の「コマンドを実行する」。ここには、設計の決定と罠を書く。

## ユーザーの決定

- 入力欄の初めの値は、ファイルの名前。**キャレットは、名前の前**（全選択にしない）。OK とキャンセルのボタン（入力欄そのものの変更は、`.claude/rules/dialog.md` の「1 行の入力欄」）
- **出力は、コンソールに流す**（`edit` のように、標準出力を捨てて、非 0 の終了だけダイアログ、にはしない）
- 対象は、カーソル下の 1 件だけ（マークは見ない）。フォルダは、押した時点のペインのフォルダ。空・空白だけの入力は、何もしない（この行は、設計の前に示した前提で、異論が無かったもの。上の 2 つは、ユーザーの言葉）

## 層（部品（C++）+ 組み立て（Lua））

| 部品 | 役割 |
|---|---|
| `pl_spawn_shell_piped`（`osx.mm`） | `/bin/sh -c` を起動して、pid と、標準出力・標準エラーのパイプの読み口を返すだけ。起動の共通部分（`SpawnShell`）は、`pl_spawn_shell_command`（`edit` 用）と共有 |
| `ShellJobManager`（`src/ShellJob.h/.cc`） | 読み口を、毎ティック読んで、行にして、`ConsoleLog::AppendLine` に足す。子の終了を回収して、知らせる。AppKit 非依存（POSIX の `read` / `waitpid` だけ） |
| `Miata._private.run_shell(command, paths, label)`（`Application.cc`） | 起動して、実行した行（`$ label`）と、非 0 の終了（赤い行）を出す。起動の失敗は `ReportFileError` |
| `Miata.command.shell(command [, dir])`（`base.lua`） | コマンドラインの検査と、作業フォルダの前置き（`cd`） |
| `Miata.util.shell_quote(text)`（`base.lua`） | 引用するだけの、純粋な関数 |
| `x`（`resources/test.lua`） | 対象・フォルダ・初めの値（`./` と引用）・ダイアログ・コンソールを開く、の組み立て |

- **`Miata.command.shell` は Lua、起動は `_private.run_shell`（C++）で、名前を分ける**（同じ名前だと、C++ が Lua を無言で上書きする）。`run_shell` は、`privates[]`（`lua_view_trampoline` 経由: 設定の読み込み中と、ステータスバーの関数の中では、Lua のエラー）
- **`edit` は、変えていない**（出力は捨て、非 0 の終了はダイアログ。`pl_spawn_shell_command`）。括り出した `SpawnShell` を通るので、`osx.mm` の起動のしかたを直すときは、両方に効く

## 作業フォルダは、Lua の `cd` の前置き

`shell` は、`cd -- "$1" || exit; shift; ` + 利用者の行、を `run_shell` に渡し、フォルダは、位置パラメータ（`$1`）で渡す。

- **フォルダを、コマンドラインの文字列に埋め込まない**（`edit` のパスと同じ理由: 名前の中の空白・引用符・`$()` が、シェルの構文として読まれない）。`cd` に失敗したら（フォルダが消えた・フォルダでない）、`exit` で終わるので、**利用者の行は、Miata の作業フォルダでは実行されない**（`cd … && 行` にしない: 行の中の `;` の後ろが、実行される）。`shift` で、行から見た `$1` `$@` を空にする（しないと、フォルダが、行の引数に見える）
- **1 行にまとめる**（前置きの後ろで、改行しない）: シェルのエラー文の行番号が、利用者の行だけを実行したときと同じになる（`sh: nosuch: command not found`。改行すると `sh: line 2: …`）
- **C++ に、作業フォルダの引数を足さなかった**: `posix_spawn_file_actions_addchdir` は macOS 26 以降、`_np` 版は 26 で deprecated（デプロイメントターゲットは未指定）。シェルの `cd` なら、`PWD` も正しく、失敗の文に、フォルダの名前が出る。`edit` に作業フォルダが要るようになったら、同じ前置きを `base.lua` の `edit` に足せる
- `dir` は、`paths_of` に通す（絶対パスの文字列・エントリ。1 件でなければ、エラー）。省略は `pane_path()`

## 初めの値の引用（`shell_quote` と、`x` の `./`）

- **引用は、必須**: 名前を、そのまま入力欄に入れると、空白で分かれ、名前の中の `$(…)`・バッククォート・`;` が、**Enter を押しただけで実行される**（ダウンロードや展開で入ってきた、細工した名前）。`'…'` で囲み、中の `'` は `'\''` にする
- **安全な文字だけの名前は、そのまま**（読みやすさ。ふつうの名前に、引用符が付かない）: ASCII の英数字と `. _ - + , : @ % /`、0x80 以上のバイト（UTF-8 の、ASCII 以外の文字。シェルにとって、特別な意味を持たない: UTF-8 のロケールでも、`sh`・`bash`・`zsh` は、0xA0 や 0x85 を含む文字（`だ`・`ム`・U+00A0 など）を、語の区切りにしない=実測）。それ以外（`=` `~` `#` `{` `!` `^` なども）が 1 つでもあれば、引用する。空の文字列は `''`。パターンに `%w` を使わない（C のロケールで、範囲が変わる）
- **`shell_quote` は、引用するだけ**。`-` や `+` で始まる名前の `./`（コマンドが、オプションと読まないように。`+` は、`vim` や `less` が、`+コマンド` として実行する）は、パスだと知っている呼ぶ側（`x`）が付ける
- **入力欄に入れるのは、ファイルシステム上の名前**（`entry.path` の最後の部分。NFD で保存された名前は、NFD のまま: APFS 以外（exFAT・SMB など）では、NFC の名前では開けないことがある）。**UTF-8 として正しくない名前だけ、`entry.name`**（`utf8.len` で見分ける。入力欄は NSString なので、不正なバイトは入れられない。`�` に置き換わった名前が入り、その名前のファイルは無いので、実行しても、「無い」で終わる）
- **初めの値のまま確定したら、何もしない**（`x` の組み立て）: 名前だけの行は、同じ名前のコマンド（`yes`・`make` など）を、引数なしで実行してしまう（うっかり Enter を 2 回押したとき）。そのファイル自体を実行するには、`./` を打ち足す
- **限界（文書に書いてある）**: 引用が効くのは、**そのまま引数として置いたとき**。利用者が、入っている名前を `"…"`・`sh -c "…"`・`eval` の中に書き直すと、名前の中身が、もう一度シェルに読まれて、実行される（実測。そのままの引数・`$(…)` やバッククォートの中・代入・関数の引数は、安全）。埋め込みは、仕様（入力欄に名前を出す）なので、`edit` のように位置パラメータへ逃がせない

## コンソールに出すもの

- **実行した行（`$ label`）は、起動できた直後に `ConsoleLog::AppendLine` で足す**: 出力の行と同じ入口なので、標準出力の書きかけの行（`io.write` の途中）と、つながらない。出力を読むのは次のティックからなので、必ず、出力の行より前になる。端末（`rake run:*`）には、出ない（出力の行も）
- **非 0 の終了は、赤い行 `終了コード N: label` だけ**（`LogError`。診断なので、標準エラー経由=端末にも出る）。**ダイアログにしない**: 出力もエラーも、コンソールにある。`grep` の「一致なし」のような、失敗ではない非 0 で、キー入力を奪わない。0 で終わったら、何も出さない。起動そのものの失敗（`posix_spawn`・`pipe`）だけ、`ReportFileError`（ダイアログ + 赤い行。実行した行は出さない）
- `label` は 1 行にする（改行は空白）。`LogError` は、改行で行が分かれる
- **コンソールを開くのは、`x` の組み立て**（`Miata.config.set_show_console(true)`。OK の後。キャンセルでは開かない）。「エラーが出ても、自動では開かない」（`console.md`）とは別: `x` は、出力を見るための操作。部品の `shell` は、画面の方針を持たない

## 出力の読み取り（`ShellJobManager`）

- **スレッドを使わず、毎ティック（`Application::Update` の先頭。`file_operations_.Update()` の次）に、読める分だけ読む**。読み口は非ブロッキング。並行処理が無いので、ロックも、スレッドの寿命の管理も要らず、テストは `Update()` を手で回せる（決定的）。採らなかった案: (a) コマンドごとの読み取りスレッド: ティックが止まっている間も読めて、速いが、大量出力を抑える仕掛けが、時間ベース（決定的にテストできない）になり、`ConsoleLog` の mutex を、メインスレッドと奪い合う。(b) GCD の read source をメインキューで: 出し続ける子が、ランループを埋める。(c) 一時ファイルに貯めて、終了時に流す: 途中経過が見えず、出し続ける子が、ディスクを埋める
- **1 回の `Update` で読むのは、出力 1 本につき `kReadBudget`（32 KiB）まで**。読まなければ、パイプが詰まって、子の書き込みが待つ（背圧）ので、出し続ける子（`yes`）でも、1 回の `Update` の時間と、メモリ（受け口の行数の上限まで）は、増えない。全体での配分（コマンドの数で割る、など）は、していない
- **終了を知らせるのは、子が終わるまでに書いた出力を、読み終えてから**: 開いている出力の全部が、(1) 閉じた（EOF）か、(2) 終了を回収した後に、空（`EAGAIN`）を見たか、(3) 終了を回収した後に `kPostExitBudget`（256 KiB）読んだ。**(2) と (3) の印を立てるのは、終了を回収（`waitpid(WNOHANG)`）した後の読み取りだけ**（`Stream::Read` の `exited`）: 終わった子が書いた出力は、もう全部パイプの中にあるので、その後に空を見れば、読み終えている。終了の前の読み取りで立てると、読み残したまま、終了を知らせてしまう。1 回の `Update` の中では、先に回収して、後で読む（同じ `Update` で、読み終えたと分かる。逆でも誤りにはならないが、知らせが 1 ティック遅れる）。(3) は、出力の口を握った孫が、書き続けているとき（空にならない）に、いつまでも待たないため。知らせの直前に、改行の無い最後の行を出す（`Flush`）
- **子が終わっても、出力の口を握ったプロセス（裏で動かした孫）が居る間は、読み続ける**（その出力も流れる。終了の行より後になる）。全部の口が閉じたら、外す。**子が、自分で出力を閉じて動き続ける**ときは、子が終わるまで残す（回収のため）
- **終了の知らせ（`on_exit`）は、`jobs_` から外す処理の後で呼ぶ**（中から `Start` が呼ばれても、走査中の `jobs_` が変わらない。`FileOperationManager` と同じ考え方）
- 回収できないとき（`SIGCHLD` を無視している、など。`waitpid` が `ECHILD`）は、終わったものとして、終了コード 0（`pl_spawn_shell_command` と同じ）
- **破棄（Miata の終了）は、読み口を閉じるだけ**（子は止めない）。まだ動いていて、出力を書く子は、次の書き込みで `SIGPIPE` を受ける（`edit` の標準出力は `/dev/null` なので、起きなかったこと）。README に書いてある逃げ道: `… >/dev/null 2>&1 &`

## OS 層（`pl_spawn_shell_piped` と `SpawnShell`）

- **パイプの 4 つの口に `FD_CLOEXEC`**（ほかの子=`os.execute` などに、引き継がせない）。**`O_NONBLOCK` は、読み口だけ**（書き口は、子の標準出力になる。非ブロッキングにすると、パイプが詰まったとき、子の書き込みが、待たずにエラーになる）
- **起動の後、成否に関わらず、親の側の書き口を閉じる**（開けたままだと、子が終わっても、読み口に EOF が来ない=コマンドが、いつまでも片付かない）。失敗したら、読み口も閉じる
- 起動のしかた（引数は位置パラメータ・標準入力は `/dev/null`・PATH に Homebrew などの bin・自分のプロセスグループ・`POSIX_SPAWN_CLOEXEC_DEFAULT`・シグナルは既定に戻す）は、`SpawnShell` の 1 か所（`pl_spawn_shell_command` の挙動を固定するテストが、notes にある。起動のしかたを直すときは、両方の関数のテストを回す）

## 限界

- **止める機能が無い**（別の `x` で `kill` / `pkill`）。足すなら、`ShellJobManager` が pid（= プロセスグループの番号）を持っているので、`kill(-pid, SIGTERM)` と、`Start` が ID を返す形
- **端末ではない**（pty を作らない）: 対話するコマンド・色・カーソルの制御は、使えない。子の標準出力がパイプだと、まとめて書く（全バッファ）コマンドは、遅れて出る
- 標準出力と標準エラーは、別のパイプなので、行の前後は、保証しない（1 回の `Update` の中では、標準出力が先）。同時に動かしたコマンドの行は、どのコマンドのものか、分からない
- **ティックが止まっている間は、読まない**（ウィンドウのリサイズ中・メニューの操作中）。App Nap（Miata が隠れている）では、ティックが間引かれる。その間、たくさん出す子は、パイプが詰まって待つ（失わない・デッドロックしない）
- 終了を、Lua から待つ・受け取る手段は、無い。コマンドの履歴も無い

## 行の組み立て（`LineAssembler`）

起動したコマンドの出力（どこで切れて届いてもよいバイト列）を、行に分ける純ロジック（`src/LineAssembler.h/.cc`。AppKit も、`ConsoleLog` も知らない）。出た行は、呼ぶ側が `ConsoleLog::AppendLine` に渡す（`.claude/rules/console.md`）。

- **行の区切りは、LF・CRLF・CR（単独）**: CR だけで行を書き換える進捗の表示（ffmpeg・curl・rsync など。出力先が端末でなくても出す）は、**書き換えのたびに 1 行**になる。端末のように同じ行を上書きはしない（`ConsoleLog` は、行を足すだけで、書き換えない）。採らなかった案: (a) 単独の CR で、貯めた分を捨てる（最後の状態だけ出す）: CR だけが改行のファイルを `cat` すると、最後の行しか残らない。途中経過も見えない。(b) 何もしない（LF だけで分け、行の中の CR は `SanitizeLine` が空白にする）: 進捗は、改行が来るまで 1 行も出ず、出たときは、上限で切れた 1 行になる
- **CR の時点で、すぐ出す**（次のバイトを待たない。進捗が、出たときに見える）。そのため、CRLF の LF を、後から見分ける印が 1 つ要る（`cr_ended_line_`: 直前の CR で行を出した。続く CR と LF は、同じ区切りの続きで、何も出さない。文字が来たら、下ろす）
- **行頭の CR は、行にしない**（何もしない）: 「CR + 新しい内容」の形の進捗（curl）が、書き換えのたびに空行を挟まないように。CRLF だけの行は、空行になる（CR は何もせず、LF が、空の行を出す）。CR だけの空行（CR CR）は、出ない（古い Mac の改行のファイルの空行は、消える。許容）。行を出した CR に続く CR と LF は、同じ区切りの続き（CR CR LF は、1 つの区切り: テキストモードの二重変換で出る並び）
- **1 行の上限は、`ConsoleLog::kMaxLineBytes`**（呼ぶ側が渡す）。超えた分は、次の区切りまで捨てて、`truncated` の印を付ける（`AppendLine` が「…」にする）。改行の無い出力が続いても、持ち越しは上限まで（メモリは増え続けない）。`ConsoleLog` の未完の行の上限（`kMaxRawBytes` = +1）と違い、CR の分を足さない: 区切りは、行に入れないので、ちょうど上限の長さの行が CRLF で終わっても、切らない
- **どう分けて渡しても、出る行は同じ**（CRLF が、渡す境で割れてもよい）。空の `Feed` は、何も変えない。`Flush`（流れの終わり）は、持ち越している行を出して、CR の状態も最初に戻す
- バイナリ・NUL・UTF-8 として不正なバイトは、そのまま通す（整形は、受け口の `SanitizeLine`）
