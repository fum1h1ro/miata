# Miata

macOS 専用のキーボードドリブンなファイルブラウザ。
フルネイティブ AppKit で描画し、Lua スクリプトでキーバインドとコマンドを定義する。

## 技術スタック

- **言語**: C++23、Objective-C++
- **レンダリング**: フルネイティブ AppKit（`NSView.drawRect:` によるカスタム描画 + 標準コントロール。sokol/Dear ImGui は使用していない）
- **スクリプト**: Lua 5.x（コルーチンベースのダイアログ制御）
- **リアクティブ**: RxCpp（`ReactiveProperty` 等）
- **依存関係**: すべて `packages/` に Git submodule として存在（実際にビルドされるのは `lua` のみ）

## ビルド

ビルドには Rake を使用する（CMake のラッパー）。

```bash
rake cmake:debug      # Debug 用 CMake 構成を生成
rake cmake:release    # Release 用 CMake 構成を生成
rake cmake:xcode      # Xcode プロジェクトを生成
rake build:debug      # Debug ビルド
rake build:release    # Release ビルド
rake run:debug        # Debug ビルドして実行
rake run:release      # Release ビルドして実行
rake icon             # アプリアイコン(assets/AppIcon.png → resources/AppIcon.icns)を作り直す
```

成果物: `_build/debug/Miata.app` / `_build/release/Miata.app`

`.app` は単体で動く。Lua の既定の設定（`resources/base.lua`・`resources/test.lua`）とアイコンは `Contents/Resources/` にコピーされていて、実行時に読むのはそこだけ（リポジトリのソースツリーは見ない）。`/Applications` などにコピーして使える。`resources/test.lua` を直したときは、ビルドし直すと反映される。ビルドし直さずに設定を変えたいときは、[`~/.config/miata/init.lua`](#設定ファイルinitlua)に書く。

### 署名してビルドする（任意）

既定の `rake build:*` は、**アドホック署名**（リンカーがつける、実行ファイルの内容そのもので識別する署名）で `.app` を作る。このままだと、**ビルドし直すたびに、別のアプリとして扱われて、フルディスクアクセスなどの許可が外れる**（[権限のエラー](#権限のエラーmacos-の保護)）。**開発者証明書で署名すると、許可が「アプリの ID と証明書」に結び付くので、ビルドし直しても残る。**

1. **署名に使う証明書を用意する。** 自分で使うだけなら、**Apple Development** 証明書で足りる（Xcode の設定 → Accounts → Manage Certificates で作れる。確認したのは、有料の Apple Developer Program の、個人のチームの証明書）。使える証明書の一覧は `security find-identity -v -p codesigning`
2. **環境変数 `MIATA_CODESIGN_IDENTITY` に、その証明書の SHA-1 ハッシュ（一覧の左の 40 桁）か、名前を入れて、ビルドする。** `rake build:*` と `rake run:*` は、`make` のあとに、毎回、その証明書で `.app` に署名する（`make` を直接使うと、署名されない）

   ```bash
   export MIATA_CODESIGN_IDENTITY=<40 桁のハッシュ>   # ~/.zshrc などに書くと、毎回付く
   rake build:debug
   codesign -dv _build/debug/Miata.app               # TeamIdentifier が出ていれば、署名されている
   ```
3. **切り替えた直後に 1 回だけ、フルディスクアクセスを入れ直す。** システム設定の「プライバシーとセキュリティ」→「フルディスクアクセス」で、**古い Miata のエントリを「－」で外してから、署名したアプリを追加してオンにする**。一覧の既存のエントリをオンにするだけでは、中の「署名の要件」が古いまま（アドホックのハッシュ）で、署名したアプリには効かない

- 以後は、ビルドし直しても、許可が残る（ソースを変えたとき、Lua のリソースだけを変えたときで確認した）
- **同じアプリ ID（`com.fum1h1ro.miata`）の、署名の違うビルド（環境変数なしのビルド、ほかの人のビルド）を動かして、フルディスクアクセスが要る場所に触ると、macOS が許可を拒否に書き換える**。署名したものだけを動かす。外れたときは、手順 3 をやり直す
- 証明書の名前・チーム ID は、リポジトリに書かない（環境変数で渡す）。環境変数が無ければ、これまでどおり、アドホック署名のまま
- 配布用の署名（Developer ID・hardened runtime・公証）は、まだ組み込んでいない
- **署名しても、クラウドストレージ（Dropbox など）のゴミ箱への移動は、解決しない**（個人の Apple Development 署名と、署名に結び付けたフルディスクアクセスで確認した）
- `resources/` のファイルを `git checkout` などで元に戻した直後は、`.app` の中のコピーが古いまま残ることがある（macOS 標準の GNU Make 3.81 は、更新時刻を秒単位でしか比べない）。そのときは、ファイルを `touch` してから、ビルドし直す

### アプリアイコン

アイコンの**元画像**は `assets/AppIcon.png`（1024×1024 の正方形の PNG）で、`rake icon` がそれを `resources/AppIcon.icns` に変換する。`resources/AppIcon.icns` が `.app` のアイコンになる（`resources/` の中身は `Contents/Resources/` にコピーされ、`CMakeLists.txt` の `MACOSX_BUNDLE_ICON_FILE` で `Info.plist` に登録してある）。**今あるのは仮のアイコン**。差し替えるには、`assets/AppIcon.png` を自分の画像で置き換えて、次を実行する。

```bash
rake icon          # assets/AppIcon.png から resources/AppIcon.icns を作り直す(macOS 標準の sips と iconutil を使う)
rake build:debug   # ビルドし直す(rake build:release でもよい)
```

- 元画像（`assets/AppIcon.png`）と、変換後（`resources/AppIcon.icns`）の**両方をコミットする**。`.icns` はビルドに必要なので、元画像を直したら、`rake icon` で `.icns` も作り直して、一緒にコミットする
- 元画像は `resources/` に置かない。`resources/` の中身は全部 `.app` に入ってしまう（`assets/` は `.app` に入らない）
- `rake icon` は引数を取らない（変換するのは、いつも `assets/AppIcon.png`）。`rake 'icon[x.png]'` のように渡すと、エラーになる
- デザインツール（Figma・Sketch など）の元ファイルは、`assets/` に置いても、リポジトリの外に置いてもよい。書き出した 1024×1024 の PNG を、`assets/AppIcon.png` に置く
- macOS のアイコンは、角丸の形と余白（1024 の枠の中に 824 の角丸四角。macOS 11 以降の作法）を、画像の側に含める。システムは形を整えてくれない
- 正方形でない画像はエラーになる。1024 より小さい画像は、大きいサイズが引き伸ばされる（警告が出る）
- Dock や Finder に古いアイコンが出続けるときは、macOS のアイコンのキャッシュが残っていることがある（`.app` を `touch` して更新日時を変える、または Dock を再起動する）

## アーキテクチャ

```
src/
├── Application.cc/h      # 更新処理(0.05秒タイマー駆動)・イベント処理・コマンド登録（シングルトン）
├── Script.cc/h           # Lua VM 管理・C++ 関数登録・設定の読み込み（組み込みの既定の設定 → ~/.config/miata/init.lua）
├── KeyBinding.h          # キーストローク解析・モード別キーマップ管理
├── misc.h                # Flags・ReactiveProperty・MessageBroker 等のユーティリティ
├── Utf8.cc/h             # UTF-8 の検証と修復（ファイル名を UTF-8 として正しい形にする。AppKit 非依存）
├── FileOperation.cc/h    # コピー・移動（別スレッドで実行。始める前の確認 FileOperationGuard と、進捗の写し FileOperationProgress。AppKit 非依存）
├── platform.h            # OS 依存処理の抽象化（`pl_*` 関数。色・フォント・ファイル操作・ディレクトリ監視・プロセス起動等）
├── models/               # データモデル（ファイルリスト・ブラウザ状態。フォルダの履歴は PathHistory、ペインの保存用の状態は PaneState。どちらも AppKit 非依存）
└── views/                # UI レイヤー（View・BrowserView・FileListView・QuickLookView・QueryBar・ProgressOverlay・Dialog。検索・絞り込みの状態は AppKit 非依存の SearchState・FilterState。進捗パネルに何を出すかは AppKit 非依存の ProgressState。名前の照合は NameMatcher）

platforms/
└── osx.mm                # platform.h の macOS 実装。AppKit 型はここと views/*.mm にのみ閉じ込める

resources/
├── base.lua              # コアユーティリティ・ダイアログヘルパー定義
├── test.lua              # 既定のキーバインド・コマンド定義（.app に埋め込まれる。~/.config/miata/init.lua で上書きできる）
└── AppIcon.icns          # アプリアイコン（assets/AppIcon.png から rake icon で作る）

assets/
└── AppIcon.png           # アプリアイコンの元画像（1024×1024。.app には入らない）
```

## 一覧の右側の表示

各行の右側には、サイズ（`1.5K` など）と更新日時が出る。フォルダとリンクは、サイズの代わりに札が出る。

| 札 | 何か |
|----|------|
| `<DIR>` | フォルダ |
| `<LNK>` | シンボリックリンク（ファイルへのもの・フォルダへのもの・リンク先が無い壊れたもの、どれも） |
| `<ALIAS>` | Finder のエイリアス（Finder の「エイリアスを作成」で作る、リンク先を指す通常のファイル） |

- リンクは、リンク先の種類に関わらず、札が出る（フォルダへのシンボリックリンクも `<LNK>`。以前は `<DIR>` と出て、フォルダと見分けられなかった）。リンク先のサイズは出ない
- **札の部分（`<LNK>` と `<ALIAS>`）だけ、別の色で出る**（既定は、`<LNK>` が黄色、`<ALIAS>` がピンク）。色は `Miata.config.color.symlink` / `alias` で変えられる（[設定](#設定)）。名前と更新日時の色は、これまでどおり、行の色（フォルダへのシンボリックリンクは、札だけが黄色で、名前と更新日時はフォルダの色。エイリアスは通常のファイルなので、ファイルの色。フォルダへのエイリアスも）。`<DIR>` とサイズは、行の色のまま
- 変わるのは表示だけ。並べ替え・[`is_dir`](#状況の取得)・Enter の動き（フォルダへのシンボリックリンクは、これまでどおり、フォルダとして入れる）は変わらない
- 壊れたシンボリックリンクは、更新日時が出ない（リンク先の更新日時を読むため）

## マウス操作

基本はキーボード操作で、ファイル一覧でマウスを使うのは**マーク済みファイルのドラッグ&ドロップ**（Finder・ターミナル・メール・ブラウザ等、他アプリへの持ち出し）だけ。ダイアログでは、選択リストの行をクリックで選べる（下記）。

- ファイル一覧上でマウスをドラッグすると、**そのペインの、見えているマーク済みファイル**をまとめてドラッグできる（[絞り込み](#絞り込み)で隠れている行のマークは運ばない）。どの行を押して始めても同じで、画面表示順に運ぶ。
- マークが1件も無いとき、およびダイアログ表示中は何も起きない。プレビュー（[Quick Look](#プレビューquick-look)）で覆っている範囲でも起きない。
- コピーになるか移動になるかはドロップ先と修飾キー（Option でコピー等）に従う。ドロップが受理されると、ファイルが移動されていれば一覧を再スキャンし（カーソルは維持され、移されなかったファイルのマークは残る）、そうでなければ、運んだファイルのマークだけ解除する（実ファイルの状態を見て判断するため、反映は 0.3 秒ほど遅れる）。キャンセルされた場合はマークを維持する。
- 自アプリのもう一方のペインへのドロップには未対応（ペイン間のコピー/移動は `copy_marked` / `move_marked` を使う）。
- ダイアログの選択リスト（[`dialog_custom`](#dialog_custom) の `select`）の行は、クリックでも選んで閉じる。行の上で押して、同じ行の上で離したときだけ確定する（押しただけ、行の外で離したときは何も起きない）。

## ディレクトリ監視（自動リロード）

各ペインは表示中のディレクトリを macOS の FSEvents で監視していて、外部（Finder・ターミナル・エディタ・ダウンロード等）で、直下のファイルが**追加・削除・改名・更新**されると、0.3 秒ほど待って自動で一覧を再読み込みする。カーソルとマークは `reload` と同じく維持される。サイズや更新日時の変化（追記、保存など）も自動で反映される。

- 短時間に続く変更は 1 回にまとめて反映する。変更が続く間も、再読み込みの間隔は最短 0.5 秒あける（走査が重いディレクトリでは、かかった時間の約 8 倍）
- ダイアログ表示中は反映を保留し、閉じた最初のティックで反映する（リネームの入力中にカーソルが動いて、別のファイルを改名してしまうのを避けるため）
- 見るのはディレクトリの**直下だけ**。サブディレクトリの中の変更では再読み込みしない
- 監視しているディレクトリ自体が消えた・移動された場合は、一覧はそのまま残る（再読み込みに失敗しても、何も表示しない）。同じ場所に作り直されると、自動で追従する
- ネットワークボリュームなど、他のマシンからの変更が通知されない場所では自動更新されない（`reload` で反映する）

## プレビュー（Quick Look）

カーソル下のファイルを、macOS 標準の Quick Look（Finder のクイックルックと同じ）で、ファイル一覧の上に被せて表示する。別ウィンドウは開かない。Lua の `quick_look` で出し入れする（`resources/test.lua` では `p` で両ペインに、`<S-p>` で反対側のペインだけに出す）。

- **プレビューするのは、カーソルのあるペインのカーソル下のファイル**（被せる範囲とは無関係）。カーソルを動かす・ペインを切り替える・ディレクトリを移動する・再読み込みでカーソルが動く、のどれでも、その時のファイルに追従する。動かし続けている間は切り替えず、止まって約 0.1 秒後に切り替える（高速に動かしたときに読み込みが空振りしないため）。一覧が空のときは空のプレビュー
- **被せる範囲**は、既定は両ペインにまたがる 1 枚。`"left"` / `"right"` を指定すると、そのペインだけに被せる（反対側のペインに出せば、カーソルのある一覧は見えたまま操作できる）
- **閉じる**のは、同じ指定でもう一度 `quick_look` を呼ぶか、`navigate_cancel`（`resources/test.lua` では Esc）。別の範囲を指定して呼ぶと、閉じずに範囲だけ切り替わる
- **キー入力を優先して、プレビューの中のクリックを要する操作はできない**（動画の再生ボタンなど）。プレビューはクリックでキーボードフォーカスを奪えてしまい、奪われるとキーバインドが効かなくなるため、クリックはプレビューに届かないようにしている。覆っている範囲では、マーク済みファイルのドラッグも効かない。**例外は、トラックパッドのピンチ（拡大・縮小）とスクロール**で、プレビューの中へ届く（キーボードフォーカスは動かない）。スクロールは、WebKit 系・テキスト系で効く。画像・PDF・json（別プロセスで描かれるもの）にも届けるが、動くかは未確認（合成したイベントでは動かなかった）。ピンチは、ズームできる種類だけ（次の項目）
- **倍率（ズーム）**: トラックパッドのピンチと、Lua の [`quick_look_zoom`](#quick_look_zoom) で変えられる（1.0 = 100%）。**ズームできるのは、中身がアプリ内で描かれる種類だけ**で、どの種類がそうかは macOS が決めている（macOS 27.0 で確認）:

  | 種類 | ズーム |
  |---|---|
  | xlsx・docx・csv・html・svg など（WebKit で描かれるもの） | できる |
  | txt・md・rtf など（テキスト） | できる |
  | 画像（png など）・PDF・json など（別プロセスで描かれるもの） | できない（macOS に、倍率を指定する手段が無い。ピンチも効かない） |

  ピンチで変えられる範囲は、種類による（WebKit 系は 100%〜300%、テキスト系は 25%〜400%）。`quick_look_zoom` は、どちらも 25%〜400%。ファイルを切り替えると、100% に戻る。拡大したら、スクロールで見渡せる（WebKit 系・テキスト系）
- プレビューの中身の見た目は macOS 標準で、`Miata.config.color` は効かない（読み込み中や空のときに見える下地だけ、`background` の色）。表示は 1 件ずつ
- ファイルの中身だけが外部で更新されても、プレビューは自動では作り直さない（カーソル下のファイルが変わったときに作り直す）

## ファイル操作の進捗（右上のパネル）

コピー・移動（`copy_marked` / `move_marked`）は別スレッドで実行されるので、実行中も一覧は操作できる。**時間のかかる操作は、ウィンドウの右上に、半透明の進捗パネルが出る。**

- **出るのは、始めて 0.3 秒たっても、まだ終わっていないとき**。速く終わる操作（小さなファイル数件など）では、何も出ない（出てすぐ消える点滅を避けるため）。出るときは、0.15 秒かけて浮かび上がる
- **1 回の操作に 1 枚**。同時に走っている操作が複数あれば、右上から縦に積む（後から始めたほうが下）。幅は 340pt（フォントが 20pt より大きいときは、その分だけ広げる。窓が狭いときは縮める）
- 1 行目は「コピー  4/12 · 25%」（種類・何件目か・割合。4 件目を処理中で、3 件を終えている）、その下に細いバー、3 行目は、いま写しているファイルの名前（フォルダの中身も、1 ファイルずつ。長ければ中ほどを省いて、拡張子を残す）。項目が 1 つだけのときは、件数は出ない
- **割合は、バイト数で数える**（終えたバイト数 / コピーするバイト数の合計）。始める前に、コピーするものを走査して、合計を調べる（その間は「コピー  準備中」で、バーは溝の中を往復する。ファイルが大量にあったり、遅いボリュームだと、長く続く）。大きなフォルダ 1 つだけのコピーでも、割合が進む。大きなファイルは、コピーの途中も進む（1 MiB ほどごと）
- **割合が出ない・すぐ終わる場合**：APFS の同じボリュームの中のコピーは、ファイルごとにクローンになるので、大きなファイルでも一瞬で終わる（パネルは出ない。ただし、小さなファイルが大量にあるフォルダは、1 つずつ作るので時間がかかり、パネルが出る）。**同じボリュームへの移動は、名前を付け替えるだけなので、バイトを数えない**（割合は、項目の数から出る。項目が 1 つだけの移動は、割合が出ない）。スキップしたファイルは、終えたものとして数える（最後まで進む）。失敗した項目は、数えない
- **完了すると、「完了」と「N件」を約 1 秒見せて**、0.4 秒かけて消える。**「完了しました」のダイアログは出さない**（出ている間は、キー操作を奪うため。0.3 秒より早く終わった操作では、一覧が更新されることが、完了の合図になる）
- **失敗したときは、パネルはその場で消えて**、これまでどおり、エラーのダイアログを出す（権限が無いときの[案内](#権限のエラーmacos-の保護)も同じ）
- **モードレス**: クリックもキー入力も受けない。パネルの下の一覧のクリック・ドラッグ・スクロールは、そのまま届く（パネルの上でも）。ダイアログや[プレビュー](#プレビューquick-look)が出ていても、パネルは出続ける（ダイアログは、パネルより手前に出る。プレビューは、パネルより奥）
- 色は、これまでの設定のもの。新しい設定は無い: 背景は `Miata.config.color.background`（透過度は 0.85 で固定。下の一覧が透けて見える）、文字と枠は `normal_text`、バーは `directory`。フォントは一覧と同じ（`set_font` / `set_font_size`）
- 実行中の操作を中止する機能は、まだ無い

## ファイル名の検索

vim の `/` のような、ファイル名の**インクリメンタル検索**。`/` を押すと、検索しているペインの下に検索バーが出る。検索語を入れていくと、**打つたびにカーソルが一致するファイル名へ飛び**、名前の中の一致した部分が強調される。一致したファイルが複数あれば、その間を `n` / `N` で巡れる。Lua の `search` などで操作する（`resources/test.lua` では `/` `n` `<S-n>`）。

- **対象は、カーソルのあるペインのすべてのエントリ**（ディレクトリも隠しファイルも）。[絞り込み](#絞り込み)をしているペインでは、絞り込んだ後の行だけが対象（`n` / `N` も件数も、見えている行だけ。絞り込みが変わると、一致が探し直される）。検索の状態は、ペインごとに独立している
- **一致するのは、検索語を部分文字列として含む名前**。検索語に**大文字が無ければ大文字小文字を区別せず、大文字を含めれば区別する**（vim の `ignorecase` + `smartcase`）。全角と半角、ひらがなとカタカナ、アクセントの有無は区別する（`e` は `é` に一致しない）。合成済みの文字と分解された文字（`が` と `か` + 濁点）は同じ文字として一致する
- **名前の中のすべての出現が強調される**（`xbarbarbar` を `bar` で検索すると 3 箇所）。カーソルのある行（今いるマッチ）の一致部分は、別の色になる。色は `Miata.config.color.search_match` / `search_current`
- **入力中**:
  - 打つたびに、**検索を始めた位置**から前方（末尾まで行ったら先頭に戻る）の最初の一致へ、カーソルが動く。その位置の行自体が一致していれば、動かない。一致が無ければ、始めた位置に戻る
  - `↓` / `↑`（`Ctrl-N` / `Ctrl-P`）で、次・前の一致へ動く。動いた先が、以降の入力の起点になる
  - 語を全部消すと、↓ / ↑で動かしていても、検索を始めた位置に戻る（以降の入力も、そこから探し直す）
  - `Enter` で確定。カーソルはその場に残る。語が空のまま確定すると、検索を始める前の状態（確定済みの検索があればそれ）に戻る
  - `Esc` で取り消し。カーソルを、検索を始めた位置に戻す。確定済みの検索があれば、その検索（語とハイライト）に戻る
  - **入力中は、Normal のキーバインドは効かない**（入力欄がキーを受けるため）。入力欄は本物の `NSTextField` なので、日本語入力（IME）がそのまま使える。変換中の未確定の文字では検索せず、確定すると検索する。`Tab` は無視する
- **確定後**:
  - `n` / `<S-n>` で、次・前の一致のファイルへ動く（端でラップ）。検索していない、または一致が無いときは、ビープ音が鳴る
  - バーに、検索語と、**カーソルのある行の順番 / 一致した件数**（`2/5`）を出し続ける。カーソルが一致の行にいないときは `-/5`。一致が無いときは「見つかりません」
  - `Esc`（`navigate_cancel`）で、カーソルのペインの検索（ハイライトとバー）を消す。Quick Look が開いていれば、それも一緒に閉じる
- **一覧が作り直されたとき**: 再読み込み（手動・[自動](#ディレクトリ監視自動リロード)・ファイル操作の後・ドロップの後）とソートの変更では、検索語を保ったまま、一致を探し直す（入力中も同じ。自動リロードはバーが出ていても止まらない）。**別のディレクトリへ移動する（入る・戻る）と、そのペインの検索は消える**
- **バー**: 検索しているペインの**下だけ**に、ペインと同じ幅で出る（[絞り込み](#絞り込み)のバーと同時に出るときは、検索のバーが一番下になる）。反対側のペインには出ず、反対側の一覧も縮まない。バーの分だけ、そのペインの一覧が縮む。左右のペインがそれぞれ検索しているときは、それぞれのペインの下に、それぞれのバーが出る（検索語も件数も別々）。検索を消す（Esc など）と、そのペインのバーだけが隠れて、一覧が元の高さに戻る。バーの出入りは、そのペイン自身の検索だけで決まるので、ペインを切り替えても一覧の高さは変わらない。[Quick Look](#プレビューquick-look) で覆っているときも、バーは覆いの手前に見える。確定後のバーは、クリックしても何も起きない（キー入力の窓口を奪わない）
- ダイアログが開くときに入力中だった検索は、確定される（ファイル操作の失敗を知らせるダイアログなどが、入力中に割り込むことがあるため）。ダイアログの表示中は、検索を始められない
- ⌘V（ペースト）は、効かないことがある（メインメニューに Edit が無いため。ダイアログの入力欄も同じ）

## 絞り込み

名前に**語を含むファイルだけ**を、一覧に残す。`f` を押すと、絞り込んでいるペインの下（[検索](#ファイル名の検索)のバーがあれば、その上）に入力欄が出て、**打つたびに一覧が絞られ**、名前の中の一致した部分が強調される。**Enter で確定すると、解除するか、別のフォルダへ移動するまで続く**。一致のしかたは 2 つ: **`f` は部分一致**（語を含む名前。一致した部分を強調する）、**`F`（Shift+f）はあいまい一致**（外部の [fzf](https://github.com/junegunn/fzf) に任せる。得点順に並ぶ。後述）。Lua の `filter` などで操作する（`resources/test.lua` では `f` と `F`）。ダイアログの絞り込み（[フォルダの履歴](#フォルダの履歴)の `dialog_filter_list`）とは別のもの。

- **対象は、カーソルのあるペインのすべてのエントリの名前**（ディレクトリも隠しファイルも）。絞り込みの状態は、ペインごとに独立している。名前以外（サイズ・更新日時など）では絞り込めない
- **部分一致（`f`）で一致するのは、語を部分文字列として含む名前**。[検索](#ファイル名の検索)と同じ規則で、語に**大文字が無ければ大文字小文字を区別せず、大文字を含めれば区別する**。全角と半角、ひらがなとカタカナ、アクセントの有無は区別する。合成済みの文字と分解された文字（`が` と `か` + 濁点）は同じ文字として一致する
- **部分一致では、名前の中のすべての出現が強調される**（あいまい一致は強調しない）。色は `Miata.config.color.filter_match`。検索の一致（`search_match` / `search_current`）と重なった文字は、検索の色になる
- **入力中**:
  - 打つたびに一覧が絞られる。**始めた直後は語が空で、全行が出る**（確定済みの絞り込みがあっても、`f` を押した瞬間に全行に戻る）。画面に見えている状態が、そのまま Enter で確定される
  - カーソルは、**同じファイルに留まる**。そのファイルが絞り込みで消えたら、一覧の並びで次に見えるファイル（無ければその前）へ動く。語を戻すと、元のファイルに戻る（一致が 0 件になっても）
  - `↓` / `↑`（`Ctrl-N` / `Ctrl-P`）で、絞り込んだ一覧のカーソルを 1 行動かす（端で止まる。折り返さない）。動いた先が、以降の入力の基準になる。語を全部消すと全行が出て、カーソルはそのファイルのまま
  - `Enter` で確定。**語が空のまま Enter すると、絞り込みを解除する**
  - `Esc` で取り消し。始める前の状態（確定済みの絞り込みがあればそれ。無ければ絞り込みなし）に戻り、カーソルは始めたときのファイルに戻る
  - **入力中は、Normal のキーバインドは効かない**（入力欄がキーを受けるため）。入力欄は本物の `NSTextField` なので、日本語入力（IME）がそのまま使える。変換中の未確定の文字では絞り込まず、確定すると絞り込む。`Tab` は無視する
- **確定後**:
  - バーに、語と、**見えている行数 / 全行数**（`3/120`）を出し続ける。一致が無いときは「見つかりません」
  - 絞り込んだ一覧の中で、普通に操作できる（`j` `k` で動く、マーク、Enter、コピー・移動…）
  - **`Esc`（`navigate_cancel`）は絞り込みを解除しない**（プレビューと検索は閉じる）。解除は、**`f` でもう一度始めて、語を空のまま Enter**。Lua の `filter_clear` でも解除できる
- **他の機能は、見えている行だけを対象にする**: [検索](#ファイル名の検索)（`/` `n` `N`）、[まとめてマークする](#まとめてマークする)（絞り込んでから `mark_all` すれば、見えている行だけがマークされる。パターンでマークの代わりになる）、ドラッグ、[プレビュー](#プレビューquick-look)、Lua の `cursor_entry` / `marked_entries`
- **隠れたマーク**:
  - 絞り込みで隠れた行のマークは、消えずに残る。**コピー・移動・ゴミ箱・リネームの対象は、見えているマークだけ**（隠れたマークは対象にならない）。見えているマークが無ければ、コピー・移動はカーソル下の 1 件を対象にする（隠れたマークは無視する）
  - バーの右端に「**隠れたマーク N**」を出す。ゴミ箱の確認にも「(絞り込みで隠れているマーク N 件は対象外です)」と出る
  - 隠れたマークを外したいときは、絞り込みを解除してから `unmark_all` する
  - ファイル操作の完了後に解除されるのは、**操作したファイルのマークだけ**
- **一覧が作り直されたとき**: 再読み込み（手動・[自動](#ディレクトリ監視自動リロード)・ファイル操作の後・ドロップの後）とソートの変更では、絞り込みを保ったまま、一致を探し直す（入力中も同じ。あいまい一致は `fzf` を呼び直す。カーソルは同じファイルに留まる）。新しく作ったファイル・リネームした先・コピー先は、**語に一致しなければ一覧に出ない**。**別のフォルダへ移動する（入る・戻る・履歴・`jump_to`）と、そのペインの絞り込みは解除される**。終了しても保存しない（[ウィンドウとペインの状態](#ウィンドウとペインの状態)）
- **バー**: 絞り込んでいるペインの**下だけ**に、ペインと同じ幅で出る。反対側のペインには出ず、反対側の一覧も縮まない。[検索](#ファイル名の検索)と同時に出るときは、**検索のバーが一番下、その上に絞り込みのバー**の 2 段になる。バーの分だけ、そのペインの一覧が縮む。入力できるのは、同時に 1 つだけ（絞り込みの入力中に `/`、検索の入力中に `f` を押すと、入力欄の文字になる）
- **ダイアログとの関係**: ダイアログが開くときに入力中だった絞り込みは、語があれば確定し、**語が空なら取り消す**（前の絞り込みに戻る。ファイル操作の失敗を知らせるダイアログなどが割り込んだだけで、絞り込みが黙って消えないように）。ダイアログの表示中は、`filter` で始められない
- **あいまい一致（`F`。Lua では `filter("fuzzy")`）**: 外部の [fzf](https://github.com/junegunn/fzf)（`fzf --filter`）に任せる。入力・確定・解除・隠れたマークなどは、部分一致と同じ
  - **文字を飛ばして一致する**（`rpt` は `report_draft.txt` に一致）。語には fzf の**拡張検索の構文**が使える: 空白で区切るとすべてに一致（AND。`rep 2024`）、`^` 先頭一致（`^re`）、`$` 末尾一致（`pdf$`）、`'` 完全一致（`'notes`）、`!` 否定（`!report`）、`|` で OR（`^a | ^b`）。語に大文字があれば大文字小文字を区別する。アクセントの有無は区別しない（fzf の既定）
  - **一覧は fzf の得点順**に並ぶ（得点が同じなら、ソートの順。絞り込んでいる間、ソートの設定は同じ得点の行の順にだけ効く）。**語が変わるたびに、カーソルは先頭の行（いちばん一致する行）へ移る**。`↓` / `↑` で動かせる。語を全部消すと全行（ソートの順）が出て、カーソルはそのファイルのまま
  - **一致した位置は強調しない**（fzf の `--filter` は一致の位置を返さないため）
  - バーのプロンプトは「あいまい」。**`fzf` が見つからない環境では、大文字小文字を無視した部分一致（ソートの順）になり**、バーの件数に「fzfなし(部分一致)」と出る（`dialog_filter_list` と同じフォールバック）。`fzf` は、`PATH` と、Homebrew の場所（`/opt/homebrew/bin`、`/usr/local/bin`）から探す。Miata を起動した環境の `FZF_DEFAULT_OPTS` も効く
  - **打つたびに `fzf` を起動する**（1 万件で 1 打鍵 5 ms ほど。10 万件は、`fzf` 単体で 10〜60 ms ほど。どちらも実測）。候補は一時ファイルに書き出す（ディレクトリを再スキャンするたびに作り直す）
  - 一致のしかたは、**始めるときに選ぶ**。確定済みの絞り込みがあるときに、もう一方のキーで始めると、全行に戻って空から入力し直す（`Esc` で、前の絞り込みを、前の一致のしかたで取り戻す）
- ⌘V（ペースト）は、効かないことがある（メインメニューに Edit が無いため。検索・ダイアログの入力欄と同じ）

## フォルダの履歴

左右のペインが**移動したフォルダを記録**して、一覧から選んでジャンプできる。履歴は**左右のペインで 1 つ**（どちらのペインで行ったフォルダも、どちらのペインからでも選べる）。`<S-h>` を押すと、その履歴が [fzf](https://github.com/junegunn/fzf) の絞り込みダイアログ（`dialog_filter_list`）に出る。絞り込んで Enter で選ぶと、**カーソルのあるペインが**そのフォルダへ移る（通常の移動と同じで、カーソルは先頭に置かれ、マーク・検索・絞り込みは消える）。Lua の `history` で操作する。

- **記録されるのは、移動に成功したフォルダ**。左右どちらのペインでも、Enter でフォルダに入る・`h` / `l` で親へ戻る・履歴から選んで飛ぶ、のどれも。再読み込み（手動・[自動](#ディレクトリ監視自動リロード)）、ソート、ファイル操作の後の再スキャンは記録しない。**起動時の場所は記録しない**（前回の場所を戻すこと（[ウィンドウとペインの状態](#ウィンドウとペインの状態)）も、初めて起動したときのホームも、移動ではないので記録しない。最初に入った先から記録が始まる。前回の最後の場所は、履歴に残っている）。移動に失敗したフォルダ（権限が無い・存在しない）も記録しない
- **一覧は、新しい順で、同じフォルダは 1 回だけ**（左右をまたいでも）。また行ったフォルダは、先頭に移る。**一覧から除くのは、履歴を開いたペイン（移動先のペイン）の今いるフォルダだけ**。反対側のペインの今いるフォルダは一覧に出るので、「反対側のペインと同じ場所を、こちらでも開く」にも使える。ダイアログは、入力が空のうちは新しい順のまま出る（`fzf` があれば、入力するとスコア順になる。`fzf` が見つからない環境では、大文字小文字を無視した部分一致になり、順は新しい順のまま）
- **長いパスは、先頭を「…」で省いて**、フォルダ名（末尾）が見えるようにする。`dialog_filter_list` の全ての行がそうなる
- **件数の上限**は `Miata.config.set_history_limit(n)`（左右のペイン**合わせて** n 件。**既定 100**、0〜10000 の整数）。上限を超えると古い方から消える（移動先のペインの今いるフォルダが履歴にあれば、それは一覧から除くので、履歴を開いたときの一覧に出るのは最大 n−1 件）。**0 にすると記録しない**（保存してあった履歴も消える）。範囲外の値や整数でない値は設定エラーになる（起動時にダイアログで知らせ、値は既定のまま）。設定の読み込みでエラーが起きた起動では、指定した上限が分からないので、保存してある履歴を削らない（上限を 10000 として扱う。設定を直して起動し直すと、正しい上限になる）。大きい値にするほど、移動のたびに保存する量と、履歴を開いたときに fzf に渡す量が増える
- **終了しても残る**。変更のたびに（0.05 秒のティックごとに、まとめて）macOS の設定に保存して、次の起動で復元する。強制終了しても、最後のティック（0.05 秒）より前の分は残る。保存先は `defaults` の `com.fum1h1ro.miata` の `MiataHistory`（文字列の配列、新しい順）。デバッグ版とリリース版で共有する。消すには `defaults delete com.fum1h1ro.miata MiataHistory`
- **上限を縮めて起動すると、古い方から消えて、上限を戻しても復活しない**。保存してある履歴に、使えない項目（相対パス、重複）があったときは、使えるものだけで復元して、起動直後に保存し直す。配列でない・文字列でない要素は読み飛ばす（ディスクの上の値は、次に履歴が変わるまで残る）
- **履歴のフォルダがもう無い**（削除・改名された、フォルダでなくなった）ときは、選ぶと「移動できませんでした」のダイアログが出て、その項目が履歴から消える。**権限が無い**ときは、許可の案内（[権限のエラー](#権限のエラーmacos-の保護)）が出て、履歴には残る。外付けディスクやネットワークボリュームを外している間に選ぶと、消えたものとして履歴から外れる
- 履歴が空のとき（記録がまだ無い・移動先のペインの今いるフォルダだけ）は、案内のダイアログを出す
- 改行を含む名前のフォルダは記録しない（fzf は候補を改行で区切るため）。`/tmp` と `/private/tmp` のように、同じ実体の別の表記は、別の項目になる。Miata を複数同時に起動したときは、最後に保存した方が残る

## ウィンドウとペインの状態

終了しても、次回の起動で同じ状態に戻る。設定ファイルではなく、自動で保存される。

- **ウィンドウの位置とサイズ**: 動かしたり大きさを変えたりするたびに保存し、次回の起動で同じ位置・サイズで開く（Cmd+Q・ウィンドウを閉じる・強制終了のどれで終わっても、最後の状態が残る）。保存されたものが無いとき（初回）は、1024×768 で画面の中央に開く。保存した位置が今のどの画面にも無い場合（外付けモニタを外した後など）は、画面内に寄せて開く
- **左右のペインがいるフォルダ**: ペインごとに保存して、次回の起動で戻す。**保存したフォルダが無い・フォルダでなくなった・開けない（権限が無いなど）ときは、黙って `$HOME` で開く**（ダイアログは出さない）。そのとき、保存した値は、そのペインのフォルダかソートを変えるまで残る（外付けディスクを外していただけなら、つなぎ直して起動すれば戻る）。シンボリックリンクは、解決せずに、保存したパスのまま戻す。戻すことは、移動として[履歴](#フォルダの履歴)に記録しない
- **ソート**: ペインごとに、基準（`name` / `size` / `mtime` / `ext`）と降順かを保存して戻す（[`sort`](#ファイル操作)で変えたもの）
- **フォーカスしているペイン**: 左右のどちらかを保存して戻す
- **保存のタイミング**: 変わるたびに（0.05 秒のティックごとに、まとめて）保存する。強制終了しても、最後のティック（0.05 秒）より前の分は残る。戻した直後は、変えるまで何も書かない
- 保存先は macOS の設定（`defaults`）の `com.fum1h1ro.miata`: ウィンドウは `NSWindow Frame MiataMainWindow`、ペインは `MiataPaneLeft` / `MiataPaneRight`（辞書: `path`・`sort`・`reverse`）、フォーカスは `MiataSession`（辞書: `focus`）。デバッグ版とリリース版で共有する。Miata を複数同時に起動したときは、最後に保存した方が残る
- 初期状態に戻すには、`defaults delete com.fum1h1ro.miata "NSWindow Frame MiataMainWindow"`（ウィンドウ）や、`defaults delete com.fum1h1ro.miata MiataPaneLeft`（`MiataPaneRight`、`MiataSession` も同様）を実行してから起動する
- **起動時の注意**: 前回のフォルダが、`~/Documents`、`~/Desktop`、`~/Downloads`、外付けディスク、ネットワークボリュームなど、macOS が保護する場所のときは、起動の途中で OS の許可のダイアログが出て、答えるまで止まることがある（[権限のエラー](#権限のエラーmacos-の保護)）。ソースからビルドし直すと許可が外れるので、また出る（[署名してビルド](#署名してビルドする任意)すれば、外れない）。応答しないネットワークボリュームのフォルダが保存されていると、起動が固まることがある（その場合は、上の `defaults delete` で消す）
- 保存しないもの: 左右のペインの境界の位置、カーソルの位置、マーク、スクロール位置、Quick Look、検索、絞り込み

## 権限のエラー（macOS の保護）

ファイルの操作（コピー・移動・ゴミ箱への移動・リネーム・フォルダの作成）や、ディレクトリへの移動・再読み込みが、**権限が無くて失敗した**ときは、エラーの内容に加えて、**許可のしかたを案内するダイアログ**を出す。（起動時に前回のペインのフォルダへ戻すのは除く。そちらは、ダイアログを出さずに、黙って `$HOME` で開く: [ウィンドウとペインの状態](#ウィンドウとペインの状態)）多くは macOS の保護（システム設定の「プライバシーとセキュリティ」）で止められた場合で、許可すれば操作できるようになる。権限が無いディレクトリへ移動しようとしたときは、移動せずに、同じ案内を出す。

- ダイアログの「**システム設定を開く**」で、システム設定の「プライバシーとセキュリティ」→「フルディスクアクセス」を開く。そこで **Miata を許可**する（一覧に Miata が無いときは「＋」で Miata.app を追加する）。許可したあと、反映されないときは、Miata を起動し直す。ダイアログの既定のボタンは「閉じる」（エラーを閉じようとした Enter で、システム設定が開いてしまわないように）
- アプリ本体（`.app`）の削除・変更は、フルディスクアクセスとは別に「App管理」の許可が要る
- **許可しても変更できない場所**がある。`/System`、`/usr`（`/usr/local` を除く）など、システム自体の領域（システム整合性保護）。ロックされたファイル（Finder の「情報を見る」の「ロック」）も、同じ「権限がありません」のエラーになるので、そのときは「ロック」を外す
- **ファイル自体の権限**（所有者・アクセス権）が原因のときも、同じ「権限がありません」のエラーになる。その場合は、許可しても解消しない。Finder の「情報を見る」の「共有とアクセス権」で確認する（ダイアログにも、その旨を添えている）
- **クラウドストレージ（Dropbox、iCloud Drive など。`~/Library/CloudStorage` の中）のファイルは、普段の起動（Dock・Finder・`open`）の Miata だと、フルディスクアクセスを許可しても、ゴミ箱へ移せない**（macOS に拒否される。既知の問題で、解決していない。開発者証明書で署名しても、フルディスクアクセスを署名に結び付けても、直らなかった）。この場合、上の案内のとおり許可しても、解消しない。**ターミナルから Miata を起動すると通る**（下の項目）。リネーム、フォルダの作成、コピー、移動も、普段の起動では失敗することがある
- **ターミナルから起動した Miata（`rake run:*`）は、許可の対象が、Miata ではなくターミナル（WezTerm、Terminal、iTerm など）になる**。macOS は、ターミナルから直接起動したプロセスの権限を、起動元のアプリのものとして扱うため。そのターミナルにフルディスクアクセスがあれば、Miata にもあるのと同じ扱いになり、上のクラウドストレージのゴミ箱への移動も通る（WezTerm で確認）。Miata 自身の許可を試すときは、`open _build/debug/Miata.app`（Finder や Dock からの起動と同じ）で起動する
- ソースからビルドした Miata は、**ビルドし直すと、許可が外れることがある**。許可はアプリの署名に結び付くが、`rake build:*` で作るアプリは、既定では「アドホック署名」（実行ファイルの内容そのもので識別する）なので、ソースを直して作り直すと、別のアプリとして扱われる。**[開発者証明書で署名してビルド](#署名してビルドする任意)すると、外れない。** 外れたときは、システム設定の一覧の Miata を「－」で外して、もう一度追加する

## 名前が UTF-8 として不正なファイル

ネットワークボリュームや FUSE など、APFS 以外の場所には、名前が UTF-8 として不正なバイト列のファイルがあり得る（APFS は、そのような名前を作らせない）。そのようなファイルがあるフォルダも、落ちずに一覧に出す。

- 名前の不正な部分は `�`（U+FFFD）に置き換えて表示する。並べ替え、検索、マークはそのまま使え、リネームの入力欄の初期値も置き換えた名前になる（初期値のまま確定しても、改名はしない）
- ファイルそのものの操作（コピー・移動・ゴミ箱への移動・リネーム・プレビュー・ドラッグ）は、元のバイト列の名前のまま行う
- **名前が不正なフォルダには入れない**（「移動できませんでした」のダイアログが出る）

## 設定ファイル（init.lua）

設定とキーバインドは Lua で書く。Miata は起動時に、次の 2 つをこの順に読み込む。**後から読んだものが、同じ設定を上書きする。**

1. **組み込みの既定の設定**（リポジトリの `resources/test.lua`）。ビルドで `.app` の `Contents/Resources/` にコピーされる。直したときは、ビルドし直す
2. **ユーザーの設定** `~/.config/miata/init.lua`。環境変数 `XDG_CONFIG_HOME` が絶対パスで設定されていれば `$XDG_CONFIG_HOME/miata/init.lua`（空や相対パスは設定されていないものとして扱う）。ファイルが無ければ読まない（エラーにならない）。ビルドし直す必要は無く、アプリを起動し直すと反映される。シンボリックリンクでもよい（dotfiles の管理用）

何が上書きされるか:

- **キーバインド**（`Miata.command.bind(mode, keys, fn)`）：同じモード・同じキーの割り当ては、後から登録したもので置き換わる。既定のキーを外すには `Miata.command.unbind(mode, keys)`
- **色・フォント・履歴の件数**（`Miata.config.*`）：後から代入・設定した値になる

エラーが起きたとき:

- アプリは起動する。エラーのダイアログを出して、ファイル名と行番号を示す。**エラーが起きた行より前の設定は有効**で、それより後は実行されない（構文エラーのファイルは、1 行も実行されない）。組み込みの既定の設定でエラーが起きても、続けてユーザーの設定を読む
- 読めないファイル（ディレクトリ、権限が無い、リンク切れ）もエラーとして示す。先頭の BOM や `#!` の行があっても読める
- ダイアログに出るのは、起動時(設定の読み込み中)のエラーだけ。**キーに割り当てた関数を実行したときのエラーは、これまでどおり標準出力に出るだけ**（ターミナルから起動していないと見えない）

読み込み中に使えるもの:

- `Miata.command.bind` / `unbind`、`Miata.config.*`、`Miata.util.*`、Lua の標準ライブラリ（`os`、`io`、`string` など）
- ファイルやペインを操作するコマンド（`navigate_*`、`reload`、`quick_look`、`history_list`、`jump_to`、`dialog_*` など）は、画面がまだ無いため使えない。読み込み中（ファイルの最上位）に呼ぶと、落ちずにエラーになる。**キーに割り当てた関数の中なら、これまでどおり使える**

```lua
-- ~/.config/miata/init.lua の例

-- Tab でペインを切り替える
Miata.command.bind("n", "<tab>", function()
    Miata.command.toggle_focus()
end)

-- 既定のキー(p = プレビュー)を外す
Miata.command.unbind("n", "p")

-- 色とフォント
Miata.config.color.directory = "#ffaa00ff"
Miata.config.set_font_size(15)
```

ウィンドウとペインの状態、フォルダの履歴は、設定ファイルではなく、自動で保存される（[ウィンドウとペインの状態](#ウィンドウとペインの状態)、[フォルダの履歴](#フォルダの履歴)）。

## Lua スクリプト API

### キーバインド

```lua
Miata.command.bind(mode, keys, function() ... end)
Miata.command.unbind(mode, keys)

Miata.command.bind("n", "j", function()
    Miata.command.navigate_down()          -- j
end)
Miata.command.bind("n", "<C-d>", function()
    Miata.command.navigate_down(10)        -- Ctrl+d
end)
Miata.command.bind("n", "<S-k>", function()
    Miata.command.make_folder()            -- Shift+k
end)
Miata.command.bind("n", "dd", function()
    Miata.command.delete_marked()          -- d を 2 回
end)
Miata.command.bind("nd", "<enter>", function()
    Miata.command.navigate_ok()            -- Enter（一覧でもダイアログでも）
end)
```

#### モード（`mode`）

| 値 | 意味 |
|---|---|
| `"n"` | Normal（通常の一覧操作） |
| `"d"` | Dialog（ダイアログ表示中） |
| `"nd"` | 両方 |

- `"N"` `"D"` のように大文字で書いても同じ
- 空文字 `""` は何も登録しない（エラーにもならない）。`n` `d` 以外の文字を含めると `unknown map` のエラーになり、**どのモードにも登録しない**（`unbind` も同じ）
- `"nd"` は、Normal と Dialog の両方に同じ関数を割り当てるが、割り当てはモードごとに別々に管理される。`unbind("n", …)` は Normal の割り当てだけを外し、Dialog の割り当ては残る（両方を外すには `unbind("nd", …)`）。割り当てが無いキーの `unbind` は、エラーになる
- テキスト入力欄にフォーカスがある間（`dialog_input`、`dialog_filter_list`）は、Dialog モードのキーバインドも効かない（テキスト入力が優先される）
- 検索バー・絞り込みバーの入力欄にフォーカスがある間（`search` / `filter` で語を入力中）は、Normal モードのキーバインドも効かない（[ファイル名の検索](#ファイル名の検索)、[絞り込み](#絞り込み)）

#### キーの書き方（`keys`）

| 書き方 | 意味 |
|---|---|
| `j` `1` `;` など | 修飾キー無しのそのキー。**大文字は Shift ではない**（`"J"` は `"j"` と同じ） |
| `" "` | スペース（1 文字のスペース。`<space>` は使えない） |
| `<S-j>` | Shift+j |
| `<C-d>` | Ctrl+d |
| `<A-x>` | Alt（Option）+x |
| `<M-x>` | Command+x |
| `<C-S-k>` | 修飾キーは `-` でつないで複数指定できる。修飾キーは `S` `C` `A` `M`（小文字も可） |
| `<enter>` `<esc>` `<tab>` `<bs>` `<del>` `<up>` `<down>` `<left>` `<right>` `<f1>`〜`<f20>` | 特殊キー（`enter` は Return、`bs` は Delete（後退）、`del` は前方削除）。`<S-up>` のように修飾キーも付けられる |
| `dd` `gg` `<C-q>s` | 続けて押すキーの列（最大 4 キー）。途中までは次のキーを待ち、どの割り当てにも合わない列を押すとビープ音が鳴って最初からやり直しになる |

そのまま書ける記号は、スペース（`" "`）と `'` `,` `-` `.` `/` `;` `=` `[` `\` `]` とバッククォートだけ。キーは文字ではなく**物理キーの位置**（ANSI 配列のキーコード）で識別する。

**注意**

- 同じモードで同じキー列を二度 `bind` すると、後の方が**黙って上書き**する（エラーにならない）。大文字の `"H"` を Shift+h のつもりで書くと、`"h"` の割り当てを上書きしてしまう。Shift+h は `"<S-h>"` と書く
- Shift を押さないと出ない記号（`?` `!` `:` など）は、直接は書けない。表にない記号を直接書くと、**`a` のキーとして登録されてしまう**。ベースのキーに `<S-...>` を付けて書く（`?` は `<S-/>`）
- 特殊キーの表にない名前を `<...>` に書くと、先頭の 1 文字のキーとして扱われる（`<space>` は `s` のキーになる）
- 修飾キーの綴りを間違えた `<X-a>` や、中身が空の `<>` を書くと、Lua のエラーではなく**アプリが異常終了する**（既知の問題）

### ナビゲーション

```lua
Miata.command.navigate_down(n)   -- n 行下（省略時 1）
Miata.command.navigate_up(n)
Miata.command.navigate_left()
Miata.command.navigate_right()
Miata.command.navigate_ok()
Miata.command.navigate_cancel()
Miata.command.current_pane()     -- カーソルのあるペイン: "left" または "right"
```

ペインは `"left"` / `"right"` の文字列で表す。`current_pane()` の戻り値は、ペインを指定する引数（`reload` など）にそのまま渡せる。

`navigate_cancel` は、ダイアログの表示中はダイアログをキャンセルし、それ以外のときは、プレビュー（[Quick Look](#プレビューquick-look)）と、カーソルのペインの[検索](#ファイル名の検索)を閉じる（`resources/test.lua` では Esc）。[絞り込み](#絞り込み)は解除しない。

`navigate_left`（親ディレクトリへ）と `navigate_ok`（ディレクトリへ入る）で、移動先が読めない（権限が無い・消えた等）ときは、移動せずに、エラーのダイアログを出す。権限が無い場合は、[許可のしかた](#権限のエラーmacos-の保護)も案内する。

`navigate_ok` は、ディレクトリへ入るだけで、ファイルでは何もしない。`resources/test.lua` では、一覧の Enter は、フォルダなら `navigate_ok`、ファイルなら [`open`](#ファイルを開く)にしている（ダイアログの Enter は `navigate_ok` のまま）。

### 状況の取得

```lua
Miata.command.pane_path([pane])       -- ペインのいるフォルダの絶対パス（文字列）
Miata.command.cursor_entry([pane])    -- カーソル下のエントリ（テーブル）。一覧が空なら nil
Miata.command.marked_entries([pane])  -- マーク済みのエントリの配列（画面の並び順。絞り込み中は、見えている行のマークだけ）。無ければ空の配列
Miata.command.current_sort([pane])    -- ソートの状態: 基準, 降順か（2つの値）
```

スクリプトから、今の状況（どのフォルダにいて、カーソルがどのファイルにあって、何をマークしているか）を読む。**読むだけで、状態は変えない**。返ったテーブルは、呼んだ時点の値の写しで、書き換えても一覧には何も起きない。`pane` は `"left"` / `"right"`（省略または `nil` なら、カーソルのあるペイン。それ以外の値はエラー）。ダイアログの表示中でも使える。

エントリは、次の 3 項目のテーブル:

| 項目 | 型 | 内容 |
|---|---|---|
| `name` | 文字列 | 画面に出る名前。NFC に正規化してある。UTF-8 として不正なバイトは `�`（U+FFFD）に置き換えてある（[名前が UTF-8 として不正なファイル](#名前が-utf-8-として不正なファイル)） |
| `path` | 文字列 | そのファイルを指す絶対パス。**ファイルシステムの名前のまま**（正規化も置き換えもしない）なので、そのままファイルの操作に渡せる。`name` と綴りが違うことがある（NFD の名前、UTF-8 として不正な名前） |
| `is_dir` | 真偽値 | フォルダか。フォルダへのシンボリックリンクは `true`（Enter で入れるか、と同じ）。壊れたリンクは `false` |

- `pane_path`: 末尾に `/` は付かない（ルートだけ `"/"`）。`jump_to` にそのまま渡せる
- `cursor_entry`: 一覧が空（ファイルもフォルダも 1 つも無いフォルダ、または[絞り込み](#絞り込み)で 0 件）のときは `nil`
- `marked_entries`: 絞り込み中は、**見えている行のマークだけ**（隠れた行のマークは含まない）。**マークが無ければ、カーソル下の 1 件にはならず、空の配列**（`copy_marked` `move_marked` は、マークが無ければカーソル下の 1 件を対象にするが、それとは違う。`delete_marked` は、マークが無ければ何もしない）。同じ対象にしたいときは、`cursor_entry` と組み合わせる（[ファイルを開く](#ファイルを開く)の例の `targets()`）。並びは、ソートに従った画面の並び順で、マークした順ではない
- `current_sort`: `key, reverse` の 2 つの値を返す（`key` は `"name"` / `"size"` / `"mtime"` / `"ext"`、`reverse` は降順なら `true`）。`sort(key, reverse)` にそのまま渡せる（`Miata.command.sort(Miata.command.current_sort())` は何も変えない）。ただし `sort` は、カーソルのあるペインだけに効く

これらを使った例は、[ファイルを開く](#ファイルを開く)を参照。

### ファイルを開く

```lua
Miata.command.open(target)             -- 既定のアプリで開く
Miata.command.open_with(app, target)   -- アプリを指定して開く
Miata.command.reveal(target)           -- Finder で表示する
Miata.command.copy_path(target)        -- パスをクリップボードへ（複数は改行区切り）
Miata.command.set_clipboard(text)      -- 文字列をクリップボードへ
```

ファイルを開く・Finder で表示する・パスをコピーする。**対象（`target`）は、いつも明示する**。次のどれか:

- パスの文字列（絶対パス。`~` は展開しない）
- エントリ（`{ path = ... }`。[`cursor_entry`](#状況の取得)の戻り値など）
- それらの配列（`marked_entries` の戻り値など）。空の配列は、何もしない

「マーク済み。無ければカーソル下の 1 件」（`copy_marked` / `move_marked` と同じ対象）にしたいときは、呼ぶ側で `marked_entries` と `cursor_entry` を組み合わせる（下の例の `targets()`）。

- **`open`**: Finder のダブルクリックと同じ。ファイルごとの既定のアプリで開く（フォルダは Finder、`.app` は起動）。複数は、ファイルごとに開く。**10 件を超えると、確認する**（「N 件を開きますか？」。既定は「いいえ」。全マークなどで、誤って何百ものウィンドウを開かないため）
- **`open_with(app, target)`**: `app` で、全部をまとめて開く。`app` は、アプリの名前（`"Visual Studio Code"`。`.app` は付けても省いてもよく、大文字小文字は区別しない）、Bundle ID（`"com.apple.TextEdit"`）、絶対パス（`"/Applications/Foo.app"`）のどれか。名前は、`~/Applications`、`/Applications`、`/Applications/Utilities`、`/System/Applications`、`/System/Applications/Utilities`、`/System/Library/CoreServices` の順に探す（ほかの場所のアプリは、Bundle ID か絶対パスで指定する）。10 件を超えると、確認する。エディタなら `open_with("Visual Studio Code", …)`、ターミナルなら `open_with("Terminal", Miata.command.pane_path())`
- **`reveal`**: Finder で、対象を選択した状態で表示する（複数は 1 つのウィンドウにまとめる）
- **`copy_path`**: 対象のパスを、改行区切りでクリップボードに置く。名前だけ・フォルダのパスだけ、などは `set_clipboard` で組む（`set_clipboard(Miata.command.cursor_entry().name)`）。UTF-8 として不正なバイトは、`�` に置き換えて置く
- **戻り値**: 要求を出せたら `true`。対象が空・確認で「いいえ」・アプリが見つからないときは `false`。**開けたかどうかは、あとで分かる**: 要求のあとで分かる失敗（開くアプリが無い、ファイルが無いなど）は、ダイアログで知らせる（複数の失敗は 1 回にまとめる）。アプリが見つからないときも、ダイアログで知らせる
- 対象が正しくない（`nil`、相対パス、NUL を含む文字列、`path` が文字列でないエントリ、入れ子の配列など）と、Lua のエラー。設定ファイルの読み込み中に呼んでも、エラー
- **シェルを通らない**（`NSWorkspace` を直接呼ぶ）ので、クォートは要らない。`$()` や空白、改行を含む名前でも、そのまま渡る。UTF-8 として不正な名前も、元のバイト列のまま渡す
- `open` / `open_with` は、確認のダイアログを待つので、キーに割り当てた関数の中から呼ぶ

`resources/test.lua` の既定のキー:

| キー | 動作 |
|---|---|
| Enter | フォルダなら入る（`navigate_ok`）。ファイルなら、既定のアプリで開く。`.app` などのパッケージはフォルダとして入る（起動するには `o`）。ダイアログでは、これまでどおり、カーソルの項目を実行する |
| `o` | 対象（マーク済み。無ければカーソル下）を、既定のアプリで開く。フォルダも `.app` も開ける |
| `<S-o>` | 対象を Finder で表示する |
| `yy` | 対象のパスをクリップボードへ |

```lua
-- ~/.config/miata/init.lua の例

-- 対象: マーク済み。無ければカーソル下の 1 件（copy_marked と同じ）。一覧が空なら、空の配列
local function targets()
    local list = Miata.command.marked_entries()
    if #list == 0 then
        local e = Miata.command.cursor_entry()
        if e then list = { e } end
    end
    return list
end

-- e: 対象をエディタで開く / t: このフォルダをターミナルで開く
Miata.command.bind("n", "e", function()
    Miata.command.open_with("Visual Studio Code", targets())
end)
Miata.command.bind("n", "t", function()
    Miata.command.open_with("Terminal", Miata.command.pane_path())
end)

-- Enter: 拡張子ごとに、開くアプリを変える（フォルダは、これまでどおり入る）
Miata.command.bind("n", "<enter>", function()
    local e = Miata.command.cursor_entry()
    if not e then return end
    if e.is_dir then
        Miata.command.navigate_ok()
        return
    end
    local ext = (e.name:match("%.([^.]+)$") or ""):lower()
    if ext == "md" or ext == "lua" or ext == "txt" then
        Miata.command.open_with("Visual Studio Code", e)
    else
        Miata.command.open(e)
    end
end)
```

- 外部のコマンドを実行したいときは、`os.execute` を使う。**終わるまで Miata が止まる**ので、時間のかかるものは、末尾に `&` を付けて待たない。`io.popen` は使えない（このビルドの Lua は、POSIX の機能を有効にしていない）ので、出力が要るときは、ファイルにリダイレクトして `io.open` で読む。パスは、シェルに渡す前に、必ずクォートする（`'` で囲み、中の `'` は `'\''` にする）

### ダイアログ

ダイアログは `NSAlert` ではなく、非モーダルな `NSView` オーバーレイ（`DialogPanel`）で表示される。テキスト入力欄は本物の `NSTextField` を使うため macOS IME（日本語入力）にそのまま対応する。

ボタンやチェックボックスを持つダイアログ（`dialog_confirm`、`dialog_yes_no`、`dialog_custom`）の中には、**カーソル**（枠が付いた項目）が 1 つある。`resources/test.lua` の既定では、`j` `k` `h` `l` と矢印キー（`<down>` `<up>` `<left>` `<right>`）で動かし、Enter でカーソルの項目を実行し（ボタン = 押す、チェックボックス = 切り替える、`dialog_custom` の選択リストの行 = 選んで閉じる）、Esc で取り消す。「既定」の見た目（強調）のボタンがあっても、Enter が押すのは、カーソルのある項目（`dialog_yes_no` は、強調したボタンにカーソルを置いて開くので、結果として、強調されたボタンが押される。`dialog_custom` は、`select` があればその行から、無ければ最初の項目から始まる）。入力欄のあるダイアログ（`dialog_input`、`dialog_filter_list`）は、入力欄がキーを受けるので、ここに書いたキー操作は効かない（[モード](#モードmode)）。

ラベルに `&x` と書くと、キー1つで項目を選べる（[項目のショートカット](#項目のショートカット)）。

#### 項目のショートカット

ボタン、チェックボックス、選択リストの行のラベルに `&x` と書くと、ダイアログの表示中に `x` キーを押すだけで、その項目を選んだことになる。カーソルをその項目に移して Enter を押したのと同じ効果で、ボタン = 押す、チェックボックス = 切り替える（閉じない）、選択リストの行 = 選んで閉じる。画面では `&` が取り除かれ、`x` に下線が付く。`dialog_confirm` のボタンのラベル（第 2 引数）、`dialog_yes_no` の「はい」「いいえ」のラベル（第 3・4 引数）、`dialog_custom` の `buttons`、`checkboxes[].label`、`select.options` に使える。

```lua
local result = Miata.command.dialog_custom({
    title      = "ソート",
    checkboxes = { { label = "降順(&D)", checked = false } },               -- d で切り替わる
    select     = { options = {"名前(&N)", "サイズ(&S)", "更新日時(&M)", "拡張子(&E)"} },  -- n s m e で、選んで閉じる
})
local yes = Miata.command.dialog_yes_no("削除しますか？", false, "はい(&Y)", "いいえ(&N)")
```

- **書式**: `&` の直後が英数字（`a`〜`z`、`A`〜`Z`、`0`〜`9`）のとき、その文字がショートカット。大文字小文字は区別しない（`&S` も `&s` も、`s` キー）。`&&` は文字としての `&`。直後が英数字でない `&`（`"Tom & Jerry"`、末尾の `&`、日本語の前の `&`）は、そのまま `&` として表示する。1つのラベルでショートカットになるのは最初の `&x` だけで、2つ目以降は `&` を取り除くだけ。日本語のラベルは、`名前(&N)` のように、英数字を添えて書く
- **押すキー**: 修飾キー（Shift / Ctrl / Alt / Cmd）なしの、そのキーだけ。キーバインドと同じく、**物理キーの位置**で見る（[キーの書き方](#キーの書き方keys)）。メインの列の数字は使えるが、テンキーは使えない
- **キーバインドが優先**: Dialog モードの[キーバインド](#モードmode)に割り当てられているキーは、そちらが動く（`resources/test.lua` の既定では、`j` `k` `h` `l`、矢印、Enter、Esc。`&j` と書いても、`j` はカーソルを動かす。下線は付く）。複数キーの束縛の先頭になっているキーも同じ。`unbind` したキーは、ショートカットとして働く
- **同じ文字が複数の項目にあるとき**: 上から順（チェックボックス、選択リストの行、ボタン）で、最初の項目だけが有効。後の項目には、下線も付かない
- **働かないとき**: 入力欄のあるダイアログ（`dialog_input`、`dialog_filter_list`。キーは入力欄が受ける）。`dialog_filter_list` の `items` と、`title`、`message` の `&` は、そのまま表示される
- **長押し**: キーリピートは区別しないので、長押しすると、連続して届く（チェックボックスは、切り替わり続ける）
- **ファイル名などをラベルに入れるとき**: `&` を `&&` にする（`label = (name:gsub("&", "&&"))`）

#### `dialog_confirm`

```lua
Miata.command.dialog_confirm("メッセージ", "ボタンラベル")
```

#### `dialog_yes_no`

```lua
local result = Miata.command.dialog_yes_no("メッセージ", default, "はい", "いいえ")
-- result: true / false
```

`default` は、開いたときにカーソルが載る（「既定」の見た目で強調される）ボタン: `true`（省略時）なら「はい」、`false` なら「いいえ」。Enter はそのボタンを押す。`h` / `l`（矢印）でもう一方へ移せる。Esc は、`default` に依らず `false`。

#### `dialog_input`

```lua
local text = Miata.command.dialog_input("プロンプト", "初期値")
-- text: 入力文字列 または nil（キャンセル）
```

#### `dialog_custom`

チェックボックス、選択リスト（縦に並んだ選択肢）、ボタンを含むカスタムダイアログ。ソート（`resources/test.lua` の `s`）の例:

```lua
local result = Miata.command.dialog_custom({
    title    = "ソート",
    message  = "説明文",              -- optional
    checkboxes = {
        { label = "降順(&D)", checked = false },   -- ラベルの &x は、ショートカット（上の「項目のショートカット」）
    },
    select = {                        -- 選択リスト（optional。1ダイアログに1つ）
        options  = {"名前(&N)", "サイズ(&S)", "更新日時(&M)", "拡張子(&E)"},
        selected = 1,                 -- 最初にカーソルがある行（1始まり。省略したら 1）
    },
})

-- result が nil ならキャンセル（Esc）
-- result.select       -- 選択リストの行で Enter（またはクリック）して閉じたときの、行の番号（1始まり）
-- result.checkboxes   -- { true/false, ... }。閉じた時点の状態
```

（実物の `resources/test.lua` の `s` は、`selected` と `checked` を [`current_sort`](#状況の取得) から決めるので、ダイアログは今のソート（今の基準の行にカーソルがあり、降順ならチェックが入った状態）から始まる。）

`buttons = {"OK", "キャンセル"}` を付けると、ボタンも並ぶ。ボタンで閉じたときは、`result.button`（ボタンの番号。1始まり）が入り、`result.select` は nil（選択は返らない）。行で閉じたときは、逆に `result.button` が nil。つまり、閉じた理由は、**行（`select`）かボタン（`button`）のどちらか一方**。

- **並び順とカーソル**: 上から、`title`、`message`、チェックボックス、選択リスト、ボタンの順に並ぶ。選択リストの行も、チェックボックスも、ボタンも、同じ 1 つのカーソルで動く。選択リストの端（先頭の行で上、末尾の行で下）を超えて動かすと、その先にチェックボックスやボタンがあれば、そちらへ移る（折り返さない）。リストへ戻ってくるときは、入ってきた側に近い行（上から入れば先頭、下から入れば末尾）に着く。
- **Enter**: カーソルの項目に作用する。**行 = その場で選んで閉じる**、チェックボックス = 切り替える（閉じない）、ボタン = 押す。行は、クリックでも選んで閉じる（[マウス操作](#マウス操作)）。
- **最初のカーソル**: 選択リストがあれば `selected` の行。無ければ最初の項目（チェックボックス、無ければボタン）。
- **`buttons` を省略したとき**: 選択リストがあれば、ボタンは出ない（閉じるのは、行の Enter か Esc）。選択リストが無ければ「OK」を 1 つ出す。`buttons = {}` は省略と同じ。選択リストがあるときは、先頭のボタンを「既定」の見た目（強調）にしない。
- **行数**: 十数個まで。スクロールも高さの上限も無いので、多いと、ウィンドウからはみ出す（大量の候補は [`dialog_filter_list`](#dialog_filter_list) を使う）。長い選択肢は、末尾が「…」で省かれる。
- **不正な引数はエラー**: ダイアログは開かず、Lua のエラーになる（キーに割り当てた関数の中なら、標準出力に出る）。`select` がテーブルでない、`options` がテーブルでない・空・文字列（数値も可）でない要素がある、`selected` が `1` 〜 `options` の数の整数でない（`2.0` は可、`2.5` と `"2"` は不可）。`select.label` など、使わないキーは無視する。`buttons` と `checkboxes` は、型の合わない要素を黙って捨てる。

#### `dialog_filter_list`

大量の文字列（`items`）から [fzf](https://github.com/junegunn/fzf) による絞り込みで1件選択する。フィルタ欄は常時表示され、上下矢印で選択移動、Enter で確定、Escape でキャンセルする。`fzf` が見つからない環境では大文字小文字を無視した部分一致に自動フォールバックする。入力が空のうちは `items` の順のまま出る（入力すると、`fzf` があればスコア順、無ければ `items` の順のまま絞り込む）。行の幅に収まらない長い文字列は、先頭を「…」で省いて、末尾が見えるように出す（パスの一覧向け）。

```lua
local picked = Miata.command.dialog_filter_list({
    items   = Miata.command.history_list(),  -- 必須: 文字列の配列（これはフォルダの履歴の例）
    title   = "履歴",              -- optional
    message = "選択してください",   -- optional
})

-- picked: 選択した文字列 または nil（キャンセル）
```

フォルダの履歴を選ぶ [`history`](#履歴) は、これを使っている。

### ファイル操作

```lua
Miata.command.mark()                -- カーソル位置のエントリをマーク
Miata.command.unmark()              -- マーク解除
Miata.command.toggle_mark()         -- マークのトグル
Miata.command.copy_marked()         -- マーク済み(無ければカーソル位置)を反対側のペインへコピー。絞り込み中は、見えているマークだけが対象
Miata.command.move_marked()         -- 同、移動。コピー/移動とも、名前が衝突する場合は上書き確認ダイアログを出す。同じフォルダへの操作などは、始める前に断る(下記)
Miata.command.delete_marked()       -- マーク済みをゴミ箱へ移動(確認ダイアログあり)。絞り込み中は、見えているマークだけが対象
Miata.command.reload(pane)          -- ペインのディレクトリを再読み込み(カーソルとマークは維持)。pane省略で現在のペイン
Miata.command.make_directory(name)  -- 現在のペインに新規フォルダを作成
Miata.command.make_folder()         -- 名前を入力ダイアログで聞いてから make_directory を呼ぶ
Miata.command.sort(key, reverse)    -- key: "name"/"size"/"mtime"/"ext"。カーソルのあるペインのソート。ペインごとに保存され、次回の起動で戻る。今の状態は current_sort で取れる（状況の取得）
```

ファイルを追加・削除・改名するこれらの操作（`copy_marked` / `move_marked` / `delete_marked` / `make_directory` / `rename`）の後も、一覧はカーソル位置とマークを維持したまま最新になる（`reload` と同じ仕組み）。カーソルのファイルが移動・削除で消えた場合は、次に残っているファイルへ寄る。`rename` のカーソルは新しい名前に付いていく。移動・削除に失敗したファイルはマークが残るので、そのまま再実行できる。`copy_marked` の後に解除されるのは、コピーしたファイルのマークだけ（操作の最中に付けたマークや、[絞り込み](#絞り込み)で隠れているマークは残る）。コピー・移動・ゴミ箱・リネームの対象は、絞り込み中は、見えているマークだけ。

**`copy_marked` / `move_marked` は、次の場合には、始める前に断る**（理由をダイアログで知らせる。上書きの確認には進まない）。どれも、そのまま進めると、ファイルを失う・コピーが増え続ける組み合わせになる。

- 反対側のペインが、**同じフォルダ**（起動直後は、左右とも `$HOME` なので、そうなる。以前は、移動で「上書き」を選ぶと、元のファイルが、ゴミ箱にも入らずに消えた）
- **フォルダを、その中のフォルダへ**（コピーが、入れ子に増え続ける）
- **移動**で、反対側のフォルダの中に、同じ名前のフォルダがあり、それが、移すフォルダの親（`/a/b/b` を `/a` へ。上書きすると、`/a/b` が、移すフォルダごと消える）

比べるのは、パスの文字列ではなく、実体（ファイルシステムの識別子）。シンボリックリンクや、大文字小文字だけが違う綴りを経由しても、同じ場所と分かる。`foo` と `foobar` を取り違えることもない。元が外部で消えた、権限が無いなど、調べられないときは断らず、項目の失敗として知らせる（その場合も、先の同名のファイルは消さない）。

**コピーの中身は、Finder のコピーと同じ作り**（`copyfile(3)`）：

- **更新日時・権限・拡張属性・ACL を引き継ぐ**（以前は、更新日時がコピーした時刻になり、拡張属性は落ちた）。フォルダの更新日時・権限も、元のとおりになる（中身を置き終えてから付けるので、読み取り専用のフォルダの中身も写せる）
- **APFS の同じボリュームの中では、クローン**になる。大きなファイルも一瞬でコピーされ、元と同じ領域を共有するので、書き換えるまで、ディスクの空きはほとんど減らない。別のボリュームや APFS 以外では、普通のコピー
- **シンボリックリンクは、リンクのままコピーする**（以前は、リンクをたどって、中身をコピーしていた）。壊れたリンクも写せる（コピー先に、同名の壊れたリンクがあるときも、同名として扱い、上書きの確認が出る）。フォルダへのリンクを、中身ごと写すことは無い（以前は、そのリンク先の中へコピーすると、自分の中へ増え続けた）
- 先に**同名のフォルダがあれば、中身を重ねる**（先のフォルダの権限・更新日時は触らない）。**同名のファイルは、「上書き」を選んだときだけ置き換える**（先が読み取り専用でも。先に別のハードリンクがあっても、そちらの中身は変わらない）。**置き換えは、同じフォルダの一時ファイル（`.miata-copy-…`）へコピーしてから、名前を付け替える**ので、コピーが途中で失敗しても（元が読めない・容量が足りない、など）、先の元のファイルは、そのまま残る。コピーしている間は、この一時ファイルが、コピー先の一覧に見える（終わると消える。Miata が異常終了したときは、残ることがある）
- **ファイルとフォルダが同名のときは、どちらも消さずに、失敗にする**（以前は、ファイルを、同名のフォルダの中へ入れていた）。FIFO・ソケット・デバイスは、コピーできない（失敗になる）
- 途中でエラーが起きた項目は、そこで止める（それまでに写した分は残る）。マーク済みの項目が複数あるときは、ほかの項目は続ける
- 新しく作ったフォルダの中で、**コピー先に同じ名前が、すでにあったときは、失敗にする**（スキップも上書きもしない）。大文字小文字を区別するボリュームから、区別しない（ふつうの）ボリュームへ、`A.txt` と `a.txt` を持つフォルダをコピー・移動すると、2 つ目が 1 つ目と同じ名前になる。黙ってスキップや上書きをすると、移動では、置かれなかったファイルの元が消えてしまうため
- **別のボリュームへの移動**は、コピーしてから、成功したときだけ元を消す（リンクは、リンクのまま移る）。**読み取り専用のフォルダ（権限 `0555` など）を含むものは、コピーはできるが、元の中身を消せず、失敗として知らせる**（先には全部ある。元は一部が残る）
- **移動の「上書き」は、先を消してから移す**ので、移すのに失敗すると（元の親に書き込めない・元が読めない・容量が足りない、など）、先だけが失われる（コピーの上書きは、上のとおり、失敗しても先が残る）。移動で「上書き」を選ぶときは、先のファイルが要らないことを確かめる

コピー・移動が終わっても、ダイアログは出ない。時間がかかる操作は、[進捗パネル](#ファイル操作の進捗右上のパネル)が、「完了」を見せる。失敗したときは、これまでどおり、ダイアログで知らせる。

複数の行をまとめてマークするコマンド（`mark_all` / `mark_range` ほか）は、[まとめてマークする](#まとめてマークする)を参照。

#### `rename`

カーソル位置の単一エントリの名前を変更する。**見えているマークが1件でもあれば何もしない**（複数選択時のリネームは未対応。[絞り込み](#絞り込み)で隠れている行のマークは数えない）。リネーム先の名前が既に存在する場合は上書きせず、衝突している旨のメッセージを添えて同じ入力ダイアログを開き直す。

```lua
Miata.command.rename()
```

#### `reload`

ペインのディレクトリを再スキャンして、一覧を最新にする。外部の変更は[ディレクトリ監視](#ディレクトリ監視自動リロード)で自動的に反映されるので、主に、監視できない場所（ネットワークボリュームなど）の変更を反映したいときや、自動更新を待たずに今すぐ更新したいときに使う。**カーソルとマークは、パスで同じファイルを引き継ぐ。**

- 引数 `pane` を省略（または `nil`）すると**現在のペイン**（カーソルのある方）が対象。`"left"` / `"right"` を渡すと、カーソルの位置に関係なくそのペインが対象になる。それ以外の値はエラー
- マーク済みのファイルが残っていれば、マークも残る。消えたファイルのマークは落ち、新しく現れたファイルは未マーク
- カーソルは同じファイルに追従する（並びが変わっても）。カーソルのファイルが消えていた場合は、再読み込み前の並びで次に残っているファイル（無ければその前）へ寄せる。対象が現在のペインでなくても同じ
- ディレクトリが消えた・読めない場合は、一覧を変えずに、失敗したディレクトリを示すエラーのダイアログを出す（権限が無いときは、[許可のしかた](#権限のエラーmacos-の保護)も案内する）

成功なら `true`、失敗なら `false` を返す。`resources/test.lua` では `<C-r>`（現在のペイン）に割り当てている。

```lua
Miata.command.reload()          -- 現在のペイン
Miata.command.reload("left")    -- 左ペイン

-- 反対側のペインを再読み込みする
local other = Miata.command.current_pane() == "left" and "right" or "left"
Miata.command.reload(other)
```

### まとめてマークする

```lua
Miata.command.mark_all([opts])           -- 全ての行をマーク（既定はフォルダ以外）
Miata.command.unmark_all([opts])         -- 全てのマークを外す（既定は全部）
Miata.command.invert_marks([opts])       -- 全ての行のマークを反転（既定はフォルダ以外）
Miata.command.mark_range([opts])         -- 直上（または直下）のマークから、カーソルの行までをマーク
Miata.command.mark_search_hits([opts])   -- 検索のヒットをマーク
Miata.command.next_mark([opts])          -- 次のマーク済みの行へ、カーソルを動かす
Miata.command.prev_mark([opts])          -- 前のマーク済みの行へ、カーソルを動かす
```

`mark` / `unmark` / `toggle_mark` がカーソル下の 1 件だけなのに対して、こちらは、ペインの複数の行をまとめて操作する。対象は、ペインの画面に出ている行（[絞り込み](#絞り込み)中は、絞り込んだ後の行だけ。隠れた行のマークは変えない。「絞り込んでから `mark_all`」が、パターンでマークの代わりになる）。**キーバインドは付けていない**（下の[例](#例まとめてマークする)で書き方を示す）。

#### `opts`

最後の引数に、省略できる表 `opts` を取る。使える項目は、コマンドごとに違う。

| 項目 | 値 | 使えるコマンド |
|---|---|---|
| `pane` | `"left"` / `"right"`。省略（または `nil`）なら、カーソルのあるペイン | 全部 |
| `kind` | `"files"`（フォルダ以外）/ `"dirs"`（フォルダだけ）/ `"all"`（全部） | `mark_all` `unmark_all` `invert_marks` `mark_search_hits` |
| `mode` | `"mark"`（マーク）/ `"unmark"`（外す）/ `"toggle"`（反転） | `mark_search_hits` |
| `from` | `"above"`（カーソルより上のマークから）/ `"below"`（下のマークから） | `mark_range` |

- **使えない項目、知らない項目、つづりの間違いは、エラー**にする（黙って無視すると、意図しない種類がマークされて、そのまま移動や削除に使われてしまうため）。`opts` が表でないとき、値が決まった文字列でないときも、エラー。エラーのとき、状態は変わらない
- フォルダかどうかは、[`is_dir`](#状況の取得)と同じ（フォルダへのシンボリックリンクはフォルダ。壊れたリンクはフォルダではない）
- 戻り値（`next_mark` / `prev_mark` 以外）は、2 つの整数 `matched, changed`: **対象になった行の数**と、そのうち、**マークの状態が実際に変わった数**。例えば `mark_all()` を続けて 2 回呼ぶと、2 回目は `n, 0`（対象は同じ `n` 行で、変わったのは 0 行）。「対象が 0 行」と「もうマークしてあった」を区別できる

#### 各コマンド

- **`mark_all`**: `kind` に合う全ての行をマークする。`kind` の既定は `"files"`（フォルダ以外。壊れたリンクとファイルへのリンクを含む）。もともとマークしてあった行は、そのまま
- **`unmark_all`**: `kind` に合う全ての行のマークを外す（絞り込み中は、見えている行だけ。隠れたマークも外すには、`filter_clear()` してから）。**`kind` の既定は `"all"`**（全解除が、フォルダのマークを残さないように）。マークが無くても、`matched` は対象の行数になる
- **`invert_marks`**: `kind` に合う全ての行のマークを反転する。`kind` の既定は `"files"`。`kind` に合わない行（既定ではフォルダ）は、触らない
- **`mark_range`**: カーソルの行から、`from` の側で、いちばん近いマーク済みの行まで、間の行を全てマークする（端の 2 行を含む。**フォルダも含む**）。カーソルの行がマーク済みでも、それは起点にしない（`"above"` なら、カーソルより上の、いちばん近いマークが起点）。**起点のマークが無ければ、何もしない**（`0, 0`）。カーソルは動かさない。`matched` は範囲の行数
- **`mark_search_hits`**: ペインの、今の[検索](#ファイル名の検索)（入力中も確定後も）のヒットの行を、マークする。`kind` の既定は `"all"`（強調されている行は、全て）。`mode = "unmark"` でヒットの行のマークを外し、`"toggle"` で反転する。ヒットでない行には触らない。**検索していなければ、何もしない**（`0, 0`）。検索は終わらせない（ハイライトも、`n` / `N` もそのまま）。検索語は、`search()` で入れて Enter で確定する
- **`next_mark` / `prev_mark`**: カーソルを、次・前のマーク済みの行へ動かす（端でラップ。カーソルの行そのものは含まない）。フォーカスのあるペインでは、画面の外の行へ動くとき、その行を画面の中央に出す（検索の `n` / `N` と同じ）。動けたら `true`。マーク済みの行が（カーソルの行以外に）無くて動けなければ `false`（ビープは鳴らさない）。`opts` は `pane` だけ

どのコマンドも、ダイアログの表示中でも使える。画面を描き直すのは、マークを変えたとき（`next_mark` / `prev_mark` は、カーソルを動かしたとき）だけ。

#### 例：まとめてマークする

```lua
-- ~/.config/miata/init.lua の例（キーは、自分の好みに合わせる）
local cmd = Miata.command

cmd.bind("n", "a", function() cmd.invert_marks() end)                        -- 反転（ファイルだけ）
cmd.bind("n", "<S-a>", function() cmd.invert_marks({ kind = "all" }) end)    -- 反転（フォルダも）
cmd.bind("n", "v", function() cmd.mark_range() end)                          -- 直上のマークから、ここまで
cmd.bind("n", "<S-v>", function() cmd.mark_range({ from = "below" }) end)    -- 直下のマークから、ここまで
cmd.bind("n", "z", function() cmd.next_mark() end)                           -- 次のマークへ
cmd.bind("n", "<S-z>", function() cmd.prev_mark() end)                       -- 前のマークへ

-- 検索（/ で語を入れて Enter）に合う行を、全部マークする（フォルダも。ファイルだけなら kind = "files"）。合うものが無ければ、知らせる
cmd.bind("n", "<S-m>", function()
    local matched = cmd.mark_search_hits()
    if matched == 0 then cmd.dialog_confirm("検索に合うものがありません") end
end)

-- マークを、全部のファイルに付け直す（前のマークは捨てる）
cmd.bind("n", "<S-i>", function()
    cmd.unmark_all()
    cmd.mark_all()
end)

-- 反対側のペインを全解除する
cmd.bind("n", "<S-d>", function()
    local other = cmd.current_pane() == "left" and "right" or "left"
    cmd.unmark_all({ pane = other })
end)
```

### プレビュー

```lua
Miata.command.quick_look(pane)        -- カーソル下のファイルのプレビューを、一覧に被せて出す/閉じる
Miata.command.quick_look_zoom(zoom)   -- プレビューの倍率(1.0 = 100%)を、指定する/読む
```

#### `quick_look`

カーソルのあるペインのカーソル下のファイルを、Quick Look のプレビューとして一覧の上に被せて表示する。動作の詳細は[プレビュー（Quick Look）](#プレビューquick-look)を参照。

- 引数 `pane` は**被せる範囲**。省略（または `nil`）と `"both"` は両ペインにまたがる 1 枚、`"left"` / `"right"` はそのペインだけ。それ以外の値はエラー。`"both"` 以外は `current_pane()` の戻り値と同じ表記なので、`current_pane()` と組み合わせて反対側のペインを指定できる
- 表示していないときに呼ぶと表示する。**表示中に同じ範囲で呼ぶと閉じる**。別の範囲で呼ぶと、閉じずに範囲だけ切り替わる
- 呼んだ後に表示中なら `true`、閉じたなら `false` を返す

```lua
Miata.command.quick_look()          -- 両ペインに被せる
Miata.command.quick_look("left")    -- 左ペインだけ
Miata.command.quick_look("right")   -- 右ペインだけ

-- 反対側のペインだけに被せる(カーソルのある一覧は見えたまま)
local other = Miata.command.current_pane() == "left" and "right" or "left"
Miata.command.quick_look(other)
```

#### `quick_look_zoom`

Quick Look のプレビューの倍率（1.0 = 100%）を指定して、指定した後の倍率を返す。どの種類がズームできるかと、トラックパッドのピンチについては、[プレビュー（Quick Look）](#プレビューquick-look)を参照。

- 引数 `zoom`:
  - 数値: その倍率。0.25〜4.0 に丸める。0 以下・NaN・無限大はエラー
  - `"in"`: 今の倍率の 1.25 倍。`"out"`: 1.25 で割る。`"reset"`: 100%
  - 省略または `nil`: 変えずに、今の倍率を返す
  - それ以外（知らない文字列、真偽値、表など）はエラー
- 戻り値は、指定した後の倍率（数値）。**何もできなかったときは `nil`**（エラーにはならない）。プレビューを表示していない、読み込み中、ズームできない種類（画像・PDF・json など）のとき。`quick_look()` で出した直後は読み込み中なので、`nil` になることがある
- ファイルを切り替えると、100% に戻る
- 既定のキーは付けていない（`resources/test.lua` に、コメントアウトした例がある）

```lua
-- 例: = で拡大、- で縮小、0 で 100% に戻す(~/.config/miata/init.lua に書く。キーは好みで)
Miata.command.bind("n", "=", function() Miata.command.quick_look_zoom("in") end)
Miata.command.bind("n", "-", function() Miata.command.quick_look_zoom("out") end)
Miata.command.bind("n", "0", function() Miata.command.quick_look_zoom("reset") end)

-- 倍率を指定する / 今の倍率を読む
Miata.command.quick_look_zoom(1.5)                -- 150%。戻り値は、なった倍率
local z = Miata.command.quick_look_zoom()         -- 今の倍率。ズームできなければ nil
```

### 検索

```lua
Miata.command.search()         -- 検索を始める(vim の /)。そのペインの下に検索バーが出て、検索語を入力できる
Miata.command.search_next()    -- 次の一致のファイルへ(vim の n)
Miata.command.search_prev()    -- 前の一致のファイルへ(vim の N)
Miata.command.search_clear()   -- 検索を消す
```

ファイル名のインクリメンタル検索。動作の詳細は[ファイル名の検索](#ファイル名の検索)を参照。いずれも、カーソルのあるペインが対象で、真偽値を返す。

- `search()`: 始められたら `true`。ダイアログの表示中、すでに入力中のとき、入力欄に文字を打てなかったときは `false`（入力中に `/` を押すと入力欄の文字になるので、キーバインドからは呼ばれない）。始まると、検索バーの入力欄がキーを受けて、**Normal のキーバインドは効かなくなる**。Enter で確定、Esc で取り消し
- `search_next()` / `search_prev()`: 動けたら `true`。検索していない、または一致が無くて動けないときは、ビープ音を鳴らして `false`。ダイアログの表示中も動かない。端でラップする
- `search_clear()`: 検索していたら `true`。ハイライトと、そのペインの検索バーを消す。カーソルは動かさない。`navigate_cancel`（Esc）も、同じことをする

`resources/test.lua` の既定のキーは、`/`（`search`）・`n`（`search_next`）・`<S-n>`（`search_prev`）。

```lua
-- ~/.config/miata/init.lua の例: <C-f> で検索を始めて、; と , で次・前の一致へ動く
Miata.command.bind("n", "<C-f>", function() Miata.command.search() end)
Miata.command.bind("n", ";", function() Miata.command.search_next() end)
Miata.command.bind("n", ",", function() Miata.command.search_prev() end)
```

検索を始めるときのカーソル位置から、前方（末尾まで行ったら先頭に戻る）の最初の一致へ動く。逆向きに探し始める機能（vim の `?`）は無い。確定後に `search_prev` で前の一致へ動ける。

### 絞り込み

```lua
Miata.command.filter(mode)                 -- 絞り込みを始める。そのペインの下に入力欄が出て、打つたびに一覧が絞られる
Miata.command.filter_set(query, pane, mode) -- 入力欄を使わずに、queryで絞り込む(確定済みにする)。空の文字列で解除。pane省略で現在のペイン
Miata.command.filter_clear(pane)           -- 絞り込みを解除する。pane省略で現在のペイン
```

名前に語を含む行だけを一覧に出す。動作の詳細は[絞り込み](#絞り込み)を参照。`mode` は語の一致のしかたで、**`"substring"`**（部分一致。省略・`nil` も同じ。一致した部分を強調する）か、**`"fuzzy"`**（あいまい一致。外部の `fzf` に任せる。得点順で、強調しない）。それ以外の値（大文字小文字違いの `"Fuzzy"`、空の文字列、文字列でない値）は、Lua のエラー。

- `filter([mode])`: 始められたら `true`。ダイアログの表示中、すでに入力中のとき（検索の入力中も）、入力欄に文字を打てなかったときは `false`（入力中に `f` を押すと入力欄の文字になるので、キーバインドからは呼ばれない）。始まると、入力欄がキーを受けて、**Normal のキーバインドは効かなくなる**。Enter で確定、Esc で取り消し。確定済みの絞り込みがあれば、いったん全行に戻って、語を空から入力し直す（Esc で前の絞り込みに戻る）。**語が空のまま Enter すると、絞り込みを解除する**
- `filter_set(query, [pane], [mode])`: `pane`（`"left"` / `"right"`。省略または `nil` は現在のペイン）の絞り込みを、`query`（文字列）の確定済みにして、**`shown, total`**（絞り込み後の行数と、全行数。どちらも整数）を返す。空の文字列なら解除する（`total, total`）。カーソルは今のファイルに留まる（隠れたら、次に見えるファイルへ。あいまい一致では、先頭の行へ移る）。入力中なら、先に終わらせる。UTF-8 として不正なバイトは U+FFFD にする。文字列でない `query`、NUL を含む `query`、不明な `pane` は、Lua のエラー（何も変わらない）。ダイアログの表示中でも動く
- `filter_clear([pane])`: 絞り込みを解除する。絞り込んでいたら `true`、していなければ `false`。カーソルは今のファイルに留まる。ダイアログの表示中でも動く。`navigate_cancel`（Esc）は、絞り込みを解除しない

`resources/test.lua` の既定のキーは、`f`（`filter()`。部分一致）と `F`（`filter("fuzzy")`。あいまい一致）。

```lua
-- ~/.config/miata/init.lua の例: x p で、名前に "png" を含むファイルを全部マークする(パターンでマークの代わり)。
-- 絞り込みは残るので、続けてコピーなどができる。x c で絞り込みを解除する
Miata.command.bind("n", "xp", function()
    Miata.command.filter_set("png")
    Miata.command.mark_all()       -- 見えているファイルだけ(既定の kind は "files")
end)
Miata.command.bind("n", "xc", function()
    Miata.command.filter_clear()
end)
```

### 履歴

```lua
Miata.command.history()               -- 履歴を選んで、カーソルのあるペインをそのフォルダへ移す
Miata.command.history("right")        -- 履歴を選んで、右のペインをそのフォルダへ移す
Miata.command.history_list([pane])    -- 履歴のフルパスの配列（新しい順。paneのペインの今いるフォルダは含まない）
Miata.command.jump_to(path, [pane])   -- paneのペインを、pathのフォルダへ移す
```

フォルダの履歴（左右のペインで共有する）。仕様は[フォルダの履歴](#フォルダの履歴)を参照。`pane` は `"left"` / `"right"`（省略または `nil` なら、カーソルのあるペイン。それ以外の値はエラー）。履歴は 1 つで、`pane` は「どのペインを移すか」「どのペインの今いるフォルダを一覧から除くか」を決める。`resources/test.lua` の既定のキーは `<S-h>`（`history`）。

- `history([pane])`: `history_list` で履歴を取り、`dialog_filter_list` で選ばせ、選んだフォルダへ `pane` のペインを `jump_to` で移す（`resources/base.lua` で定義した Lua の関数）。履歴が空なら、案内のダイアログだけを出す。選ぶのに時間がかかっても、**キーを押した時点のペイン**を移す
- `history_list([pane])`: 履歴を、新しい順のフルパスの文字列の配列で返す。**`pane` のペインの今いるフォルダは含まない**（反対側のペインの今いるフォルダは含む）。履歴が無ければ空の配列
- `jump_to(path, [pane])`: `pane` のペインを `path` のフォルダへ移す。Enter でフォルダに入るのと同じ移動（カーソルは先頭、マーク・検索・絞り込みは消える。履歴にも記録される。フォーカスは動かさない）。移れたら `true`。移れなければ、ダイアログでエラーを知らせて `false`（権限が無い失敗には、許可の案内が付く）。**そのフォルダがもう無ければ（消えた・フォルダでなくなった）、履歴からも外す**。権限が無い、一時的な I/O エラーなどで有無が分からないときは外さない。`path` は**絶対パスのみ**（`~` は展開しない。相対パス、空の文字列、**空の要素（`//`）・`.`・`..` を含むパスはエラー**。`..` を含めると、そのあとの「親へ戻る」が、実際に開いた場所の親とずれるため）。末尾の `/` は除いて移る。ダイアログの表示中でも動く

```lua
-- ~/.config/miata/init.lua の例: g d でダウンロードフォルダへ（ブックマークのような使い方）
Miata.command.bind("n", "gd", function()
    Miata.command.jump_to(os.getenv("HOME") .. "/Downloads")
end)
-- 上限を 300 件にする（左右のペイン合わせて。0 なら記録しない）
Miata.config.set_history_limit(300)
```

### 設定

```lua
Miata.config.color.background     = "#112233ff"  -- 背景（RGBA hex。alpha は使わない）。進捗パネルの背景も、この色（透過度は 0.85 固定）
Miata.config.color.normal_text    = "#aaff55ff"  -- ヘッダー（パスの表示）と、検索・絞り込みバーの文字。進捗パネルの文字と枠も
Miata.config.color.normal_file    = "#ffffffff"  -- ファイルの名前・サイズ・更新日時
Miata.config.color.directory      = "#00ffaaff"  -- ディレクトリ。進捗パネルのバーも
Miata.config.color.search_match   = "#7a5c00ff"  -- 検索で一致した部分の背景
Miata.config.color.search_current = "#c06000ff"  -- カーソルのある行の、一致した部分の背景（今いるマッチ）
Miata.config.color.filter_match   = "#5a2d82ff"  -- 絞り込みで一致した部分の背景（検索の色と重なった文字は、検索の色になる）
Miata.config.color.symlink        = "#ffd24dff"  -- 一覧の右側の札 <LNK>（シンボリックリンク）の文字。札の部分だけ（名前と更新日時は行の色のまま）
Miata.config.color.alias          = "#ff8ad8ff"  -- 一覧の右側の札 <ALIAS>（Finder のエイリアス）の文字。札の部分だけ

Miata.config.set_font("フォント名")   -- 未指定時はシステムデフォルトフォント
Miata.config.set_font_size(14)        -- ファイル一覧の行の高さも連動して変わる
Miata.config.set_history_limit(300)   -- フォルダの履歴の件数（左右のペイン合わせて）。0〜10000 の整数、既定は 100。0 なら記録しない
```

色は `"#rrggbb"` か `"#rrggbbaa"`（16 進）で書く。

- **背景は、OS のテーマ（Light / Dark）に関わらず、設定した色で塗る**（ファイル一覧、ヘッダー、検索・絞り込みバー、ウィンドウ、Quick Look の覆い）。**alpha は使わない**: `"#rrggbbaa"` と書いても、常に不透明に塗る（半透明にすると、後ろの OS のテーマの色が混ざるため）。**例外は、進捗パネルの背景だけ**で、背景色の RGB に、固定の透過度（0.85）を掛けて、下の一覧を透かす（設定の alpha ではない）。
- 背景の明るさに合わせて、ペインの境目の線やスクロールバー（OS が描く部品）は、暗い背景なら Dark 用、明るい背景なら Light 用の色になる。
- **タイトルバーと、ダイアログ（`dialog_*`）は、これまでどおり OS のテーマに従う**（`Miata.config.color` は効かない）。
- 既定の設定（`resources/test.lua`）は、暗い背景に明るい文字の配色。背景を明るくするときは、`normal_text` と `normal_file` も暗い色にする（検索の一致部分の背景 `search_match` / `search_current` と、絞り込みの `filter_match` も、既定は暗い背景用の暗い色なので、明るい色に変える。札の文字 `symlink` / `alias` は、既定が暗い背景用の明るい色なので、暗い色に変える）。

これらは、[`~/.config/miata/init.lua`](#設定ファイルinitlua) に書いて、組み込みの既定の設定を上書きできる。設定は起動時にだけ読み込む（変えたら、起動し直す）。
